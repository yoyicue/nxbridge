# NXB-035：实验性本地 Mach 媒体协议

状态：实验实现，供隔离运行验证；尚不是 NXBridge Host / Rust worker 的正式接口。描述符语义以 [媒体 ABI v1](media-abi-v1.md) 为准，Mach 消息只定义本机进程间的传输，不直接发送 C 结构布局或进程本地端口数字。

worker 在独立进程创建接收端口，在启动游戏子进程时传递 Mach 发送权；游戏进程对每次运行使用非零会话 ID 和代次。此实验使用独立进程的 `mach_ports_register` 空闲槽传递初始端口，不将该机制当作已验收的产品启动接口。

## 视频

源最多持有六个 IOSurface-backed BGRA CVPixelBuffer，并最多同时写入一个。它先发送注册消息，携带会话、代次、缓冲 ID、尺寸以及 IOSurface 和回复端口的 Mach 权限；worker 导入表面，验证尺寸、像素格式、行跨度、分配大小及同一代次内 ID 和表面身份。源只在收到匹配的注册确认后发布该缓冲。丢失确认时允许重试；worker 仅对同一 ID、同一表面的重复注册幂等确认，其他重复注册拒绝。错误会话、代次、缓冲 ID 或带序号的注册确认不会激活槽位。

帧在 GPU 完成回调后发送，带序号、单调时间戳、时长、缓冲 ID 与实际 IOSurface 权限。worker 只接收已登记且未在途的对象，最多保留三个待编码帧、两个 VideoToolbox 在途帧；待编码队列满时释放最旧帧。完成、丢弃和失败分别返回不同释放结果。源只接受匹配当前会话、代次、缓冲 ID 和序号的释放；已发出但未归还的缓冲不会因等待超时而重用。源总池限六个；第六个租约可短暂在传输中，直到 worker 返回被淘汰的旧帧。Mach 通信队列最多三条，发送不等待；若通信队列本身已满，源仍只能拒绝新帧，尚未实现跨传输队列淘汰最旧帧。当前将 BT.709 作为实验色彩假设，实际色彩元数据尚未验证。

## 音频

游戏静音消费者按自身节奏推进 PCM，单生产者 / 单消费者队列最多缓存 20 块。实验源把 48 kHz 立体声 F32 样本、首样本序号、PTS 和间断标志以内联字节复制进 Mach 消息；发送失败后下一块标记间断。worker 校验会话、代次、序号、样本范围及连续时间戳，将数据复制到其本地注册缓冲并同步消费、释放。另有实验路径通过私有 Unix 数据报向 Rust GameStream 传输 PCM；worker 的数据报发送失败时，后续成功块也标记间断。数据报的发送及接收缓冲分别设为 32 KiB，本机可容纳约 16 个音频块。GameStream PCM 接口携带会话、代次、时间戳与间断标记；过载时丢弃并标记，空队列时短缺口最多补四个 5 ms 静音块，长缺口或积压时重新对齐并限制发送节奏。真实 Pad 实测仍有发送失败和客户端积压，音画同步和可靠性尚未验收，详见 [NXB-107](reports/NXB-107.md)。此路径不实现跨进程共享 PCM 缓冲句柄。

## 停止与验证边界

正常停止先停止源并排空 GPU，再等待已发出的租约归还。worker 崩溃后仍持有未归还标记的槽位不再被源复用；停止等待超时后保留这些对象直到源进程结束。新进程使用新代次，不能从旧代次接收帧或释放。测试覆盖了正常注册、错误会话 / 代次的注册确认、慢消费者、worker 在持有缓冲时被终止与独立重启，详见 [NXB-035](reports/NXB-035.md)。尚未验证同一源进程绑定新 worker、长期稳定性、游戏色彩、音画内容同步和独立显示器状态。

worker 收到与当前待编码或编码中租约完全相同的重复帧时，只丢弃消息及其端口权，不发送失败释放，避免源在原始帧仍被使用时复写。独立测试覆盖重复消息及实际 IOSurface 待编码对象；它不替代真实 GPU 故障与跨进程端到端验证。
