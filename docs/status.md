## 用户确定的方向

- 名称 NXBridge；使用独立项目目录。
- 自有代码默认采用 MIT；第三方内容及另有声明的集成包保留各自许可。
- 面向 NX2Apple / nxnative 的高性能局域网串流，Mac 运行 BOTW，Android Pad 操控。
- 项目以 agent 驱动开发，需要可执行的任务、设计、验证和交接约定。
- 产品按多游戏设计，BOTW 为首个验证对象；后续采用内置 Web 管理界面，Web、CLI 和 agent 共用 Host 管理 API，各游戏及混合并发分别验收。
- 家里有 2–3 位玩家，实例化和隔离必须进入设计。暂按同时独立游玩设计，也兼容轮流模式；并发数量待测。
- 已讨论虚拟化和 Lima：首轮采用原生 macOS 多进程，Lima 不作为依赖。
- 正式目标改为 NXBridge Rust GameStream 兼容服务端，直接管理 nxnative 并接收离屏帧 / PCM；Sunshine 保留为对照与过渡，NX2Apple 构建工具继续复用，运行时无需其 GUI。
- 首个原生版本在已登录用户会话中无可见游戏窗口；无物理显示器、锁屏、未登录能力单独验证。长期面向“Mac 家庭共享主机 + Pad 个人入口”，当前不承诺跨主机实时迁移或并发容量。

## 已观察的环境

2026-11-02 的只读检查：Mac mini Apple M4、16 GB、macOS 26.5、Xcode 26.5。1402 是 TALIH-PD2、MT8797Z/CNZA、Mali-G77 MC9、8 GB、Android 13；系统声明 `c2.mtk.avc.decoder` 和 `c2.mtk.hevc.decoder`。这些是环境信息，不是串流性能证明。

此前 Cemu / Wii U 的测试在相邻 botw-talih-port 项目中：540p 开场 3D 采样约 3.6 FPS；360p 两次读档被 LOW_MEMORY 结束。该结果不用于预测 NXBridge 的容量。1402 上 Cemu、自研与另一套 Switch 测试程序均已按用户要求删除；电脑上的备份保留。

历史实验原始证据保留在本机，不纳入本仓库；不要复制其中的游戏或私人存档。

## 已知缺口

- 最新 nxnative 默认工具链要求高于当前机器；实验以非锁定 Metal 编译器运行成功，但正式兼容路线仍未完成。
- 上游 BOTW M4 Pro 记录不是本机 M4 成绩；本机游戏单实例基线还没有。
- Sunshine 稳定参考版 macOS 手柄未支持；主线的授权 Broker 不作为全开源方案前提。
- Rust 合成音画服务端已通过单客户端 Moonlight 原型验收；其协议核心为 GPL-3.0-only 保守管理的 Moonshine 派生版本，FFmpeg 负责合成源的 VideoToolbox 编码。真实游戏离屏媒体已有实验实现，正式媒体契约和同步仍未验收。
- nxnative 默认 title 级数据目录、遮挡节流、最小化暂停、物理手柄合并都需要多实例适配 / 验证。
- 单游戏进程已有原生协议触屏输入原型；两路不同端点已有短时配对、画面和单按键隔离探索，音频、存档、断线和故障的完整多会话隔离尚未验收。
- 桌面 / 单游戏视频串流已有短时探索性观察；音频授权后编码初始化成功，但平板声音尚未听验。端到端延迟和重连尚未测量，多会话容量未知，measured_session_capacity 必须保持 null。
