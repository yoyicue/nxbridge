# 存储、缓存与临时文件

状态：设计及 S2Arm 独立缓存接口已实现；本机日常数据已部分迁移，统一安装、自动管理和安全清理尚未实现。此文不赋予删除现有文件的权限。

## 原则与目录

目录按丢失的后果分类，不以生成方式、大小、目录名或能否从头构建判断。日常运行依赖必须有明确所有者和生命周期，不能仅因为出自一次实验就放在可随意清理的实验目录。用户可以自行选择持久数据、缓存与临时文件所在卷；跨卷复制可能需要完整额外空间。

以下是拟定布局，路径仅作示意，尚未被 Host 自动使用：

```text
storage/                              # 持久化，备份和迁移
  host/                              # 配对身份、配置、数据库
  library/<title>/<build>/           # 已安装的游戏构建与必要资源
  runtimes/<backend>/<revision>/     # 日常使用的引擎、worker、工具和清单
  profiles/<player>/<title>/save/    # 玩家存档和后端持久状态
  backups/                           # 经校验的备份与恢复清单
cache/                               # 有身份、可重建，但清理有成本
  <backend>/<player>/<title>/<build>/
tmp/                                 # 会话私有，退出后可按归属回收
  sessions/<session-id>/<generation>/
```

| 分类 | 内容与规则 | 清理影响 |
| --- | --- | --- |
| 持久数据 | 存档、配对身份和密钥、用户配置、游戏库元数据与封面；已安装游戏构建、ROM 提取结果及其引擎、worker、必要工具和清单 | 不能由临时文件或缓存清理器移除；备份受权限和隐私保护 |
| 缓存 | 可重新生成的 shader / pipeline、编译下载缓存；按引擎、构建和平台身份隔离 | 清理后可能需要原材料、工具、很长编译时间和额外空间，还会重新出现首遇卡顿；不等于可以无条件删除 |
| 临时数据 | 会话工作目录、可丢弃的中间文件；会话结束并完成写入、释放和归属核验后才可回收 | 运行中、崩溃恢复中、被现有配置引用时不能清理；日志和诊断如需保留应先单独归档 |

持久位置、外接盘、NAS 的挂载身份、可用空间、文件系统语义和备份状态均需核验。游戏资源和引擎目录只读使用；存档的写入与备份遵循 [会话隔离](sessions.md)。配对材料和诊断可能包含秘密，不进入版本库。安装工具和用户提供的游戏 / 密钥资源保持合法归属，不打包到源码。

## 当前代码的实际边界

- S2Arm 的 `DM_SAVE` 存放该玩家持久状态，`DM_TEMP` 存放每代会话工作文件。设置 `DM_CACHE` 时，管线与 shader 缓存位于该目录的 `.s2arm-cache/<身份>`，带现有身份检查和排他锁。三个目录必须是已存在的绝对目录且相互独立，缓存也不能与引擎或游戏资源重叠。
- 为兼容已部署配置，未设置 `DM_CACHE` 时仍使用 `DM_TEMP/.s2arm-cache`。因此旧 `DM_TEMP` **并非纯临时目录**，不能按本设计直接清空。此前版本的适配器不认识 `DM_CACHE`；需要重新准备、核对并部署引擎后才生效。
- GameStream 目录校验会拒绝不同游戏的可写目录重叠；配置的 `DM_CACHE` 也参与此校验。它不会创建目录、进行迁移、运行垃圾回收，也不代替其他后端各自的存储语义。
- Host `config/local.example.json` 的 `storage_root` 仍是示例，运行时未读取；产品目录选择、权限、迁移、备份和安装还没有统一实现。macOS 系统临时目录可能被系统回收，不应承载未提交的存档或唯一恢复数据。

## 迁移与回退要求

1. 清点服务配置的实际引用，包括启动器、二进制、工具链、sandbox、游戏目录内符号链接与 ROM 资源、封面、配对状态、玩家存档和缓存。核对每个引用存在、来源版本、可用性及归属。当前失效引用应报告缺失，不能把其父目录或相似名称当成可用的替代品。
2. 在会话停止并持有对应存档 / 缓存写者锁时，先建立可校验备份。复制到新位置，保持或明确重写内部链接；校验文件、目录和版本身份，校验目标卷空间及断电恢复能力，不覆盖原路径。
3. 使用独立配置和存档副本验证启动、读档、退出、sandbox、输入、音画及缓存身份；按游戏分别验证。再对空闲服务切换配置并保留原配置、原资源与已验证回退步骤。不得让两个进程同时写同一存档或缓存。
4. 完成实际客户端验收和恢复演练后，才对明确归属且不再引用的旧数据考虑另行清理；在此之前原路径仍为恢复所需。不要把系统工具、游戏本体或外部资源一并清除。

本机 OoT 的新构建已将 ROM 链接目标一并迁入持久区域；单独复制游戏根仍会造成断链。两台 Pad 的三游戏配置、存档和缓存已迁入新布局，BOTW / TOTK 游戏资源仍依赖原外部数据卷。当前清理及备份恢复机制未实现，历史路径已不是最新玩家数据；具体结果和剩余限制见 [NXB-136](reports/NXB-136.md)。
