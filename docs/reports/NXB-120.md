# NXB-120：虚拟手柄编辑与游戏布局（进行中）

日期：2026-11-09。任务状态以 `tasks/backlog.json` 为准。

## 目标与范围

基于固定 Moonlight Android 修订 `b48494cb96bff23d8886c4775cc4f39a1075495d`，在游戏库和串流内提供相同的布局编辑，并按游戏和设备方向保存。服务端提供稳定游戏库身份。此记录同时说明为后续手感与输入可靠性任务做的独立试验，不代表 NXB-121 或 NXB-122 已验收。

## 已实现

- 游戏库菜单 / 按钮和串流内齿轮可以进入布局草稿，包含移动、缩放、试按、撤销、上个版本、默认位置、取消和保存。试按只更新本机状态；编辑期间暂停本会话输入，尝试中和原有状态。
- 每台设备本地按游戏库 ID、方向和摇杆模式隔离布局；无新游戏 ID 时回退到主机和应用 ID。按修订检测冲突、原子写入并保留历史；旧 OSC 设置不被删除或覆盖；可将旧通用或旧主机布局导入草稿，并显式保存到当前游戏。历史文件保留上限为 128，达到上限后拒绝保存。
- 提供候选小手紧凑、标准、大屏靠边预设；左右浮动摇杆可单独调整死区、满量程、指数和双击手势，L3/R3 也可选择显示为独立按钮，本机触碰反馈单独开关且默认关闭。恢复默认位置保留摇杆参数。当前曲线设置只覆盖浮动摇杆。
- `adapters/input/nxbridge_input.c` 试验将按钮变化保存在八项有界快照队列，每个游戏采样至多消费一项，摇杆单独变化保留最新值；溢出立即中和并等待全中和后恢复。配置会话时玩家 0 不再合并未经分配的 Mac 本地手柄，即使接收器配置错误也中和；未配置会话时保留原有本地输入。此隔离不代替 Mac 本地手柄分配或 Pad 上实体手柄与触屏的来源仲裁。新版接收器已部署到两路本机实验游戏引擎；队列可能在密集边沿期间延长排队，仍需测量。
- 触屏与 Pad 的实体手柄在客户端按主要来源仲裁：有效操作触发切换，先中和旧来源，旧手柄按住状态必须回到中和才能再次接管；小轴噪声不会接管或触发上游连接时的全零帧。Mac 本地手柄仍需 Host 显式分配。
- GameStream 上游队列溢出、控制端明确断开或加密控制消息静默 215 毫秒时推进输入代次，输入桥发送 `NXIR` 中和帧以清空接收器中尚未采样的边沿，并拒绝旧代次，直至当前代次收到全中和；媒体会话超时与输入静默检测分开。更短的静默阈值减少网络抖动余量，250 ms 是失联到游戏中和的目标而非该阈值，也不是所有网络条件下的保证。具体对照见 [输入失联时序实验](NXB-120-input-liveness.md)。
- 新版 GameStream 输入桥和新版引擎接收器必须配套部署：旧接收器不理解 `NXIR`，收到后会断开本地输入连接。不能只替换其中一端；回滚时也要一起恢复。
- 客户端修改以 `adapters/input/moonlight-layout-editor-350.patch`、`moonlight-layout-validation-351.patch`、`moonlight-safe-area-353.patch`、`moonlight-layout-commit-354.patch`、`moonlight-input-lab-356.patch`、`moonlight-layout-recovery-357.patch`、`moonlight-layout-history-359.patch` 和 `moonlight-layout-transfer-363.patch` 依次保存，基于先前 331 版本，许可与适用修订见 `adapters/input/NOTICE.md`。它们是实验补丁，完整干净构建链和正式发布尚未完成。
- 353 将 [Android 窗口手势和刘海 insets](https://developer.android.com/reference/android/view/WindowInsets.Type) 与控件容器相对窗口的位置及父视图可见范围相交。编辑器显示安全区，拖动、缩放和保存受此边界限制；旧布局载入时临时适配并提示，只有明确保存才写新修订。系统区域变化时清理触点并重新加载；旧布局适配后发生冲突则显示回退布局，保留原文件。
- 356 在游戏库长按游戏卡片进入“输入工作台”，以选中游戏的当前布局复用生产触屏控件、实体手柄解析和来源仲裁；输出被接到本机诊断接收器，不启动游戏。面板显示按键、四轴、来源及各控件触点归属；最多保留 128 条单调时钟事件，支持清空或由玩家主动复制，退出后记录消失。它不采集视频，也不代表主机或游戏实际采样。
- 357 对可读取且不超过 8 MiB 的无效布局提供显式恢复：可先预览最近的有效历史；确认后比较文件指纹，备份原文件，再原子保存草稿，已有历史保持不变。恢复前文件发生变化时拒绝覆盖。备份保存在应用私有目录；387 已提供通过系统选择器导出，直接从损坏备份恢复仍不支持。

## 结论与限制

不能以 ADB 触摸声称真实握持舒适或震动正常。实体手柄中和与切源、编辑时断线、更多短按时间边界和游戏实战、远端静默的 250 ms 目标、多种两会话故障及长期隔离尚未完整验收。触屏与模拟手柄的来源切换已实现并做事件注入验证，实际实体手柄及更多机型仍待验收；本机转发心跳不证明远端仍在线。工作台只观察本机客户端输出，实际游戏输入采样、动作效果和端到端延迟仍须分开测量。旧布局可显式导入，但尚无玩家配置层、完整导出和管理 API 协同；安全区只在这两台同型号设备及一次软件模拟刘海上验证，其他系统版本、游戏内刘海变化和保存时转屏竞态仍待真机验证。损坏文件备份可从游戏库编辑器导出，但不能直接还原；超出 8 MiB 或无法读取的文件不提供自动恢复；更多非法配置及与管理 API 的并发冲突需补测。外观淡出和高对比度已做候选开关，并在 1372 的 BOTW 标题画面比对闲置和按下截图；亮暗场景及真实握持体验仍待验收。
