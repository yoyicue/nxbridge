# NXB-120：面键联动缩放

日期：2026-11-09。任务状态以 `tasks/backlog.json` 为准。

客户端 379 的“面键联动”同时适用于移动和大小模式：开启联动后选“大小”，拖动任一面键可围绕面键组的中心等比缩放四个命中矩形，保留 Switch 面键相对顺序；选择“试按”会关闭联动。缩放按本次触点开始时的布局重新计算，避免多次触摸事件累计取整漂移。候选同时检查 48 dp 最小触摸尺寸、安全区、设置入口、组内及与其他启用控件的矩形冲突，不通过时保留最后一次有效大小。取消、撤销和保存沿用现有布局事务。小尺寸仍须真实手指验证，48 dp 只是候选下限。

## 验证

- 1372：以小手候选布局为起点，四个面键均从 120 px 缩到约 101 px，ZL / ZR 未变化；继续缩小时最后有效的面键为 98 px（设备 320 dpi，48 dp 为 96 px）；尝试继续放大时最后有效大小为 159 px、右缘约 x=2495，未超出安全区右缘 2500。调整后撤销并保存，控件配置与撤销前修订一致。各过程记录在本机 `.nxbridge/controller-120/379-before.json`、`379-shrink.json`、`379-min.json`、`379-max.json` 和 `379-undo.json`。
- 1402：相同布局和模拟手势下四个面键均从 120 px 缩到 100 px，ZL / ZR 几何不变；保存为新修订。首次脚本把结果限定为恰好 101 px 而失败，修正为 99–102 px 的采样容差后通过；这是模拟手势事件采样的差异，不是尺寸性能结论。记录为本机 `.nxbridge/controller-120/379-1402-before.json`、`379-1402-shrink.json`。两台测试配置和历史均已删除，未启动游戏或改动存档。
- `tests/FaceGroupResizeTest.java` 覆盖等比放大 / 缩小、最小尺寸、安全边界、障碍、非有限比例以及相邻边界取整；`tests/FaceGroupMovementTest.java` 回归通过。固定 Moonlight 修订 `b48494cb96bff23d8886c4775cc4f39a1075495d` 的 NXBridge 378 源应用 `moonlight-face-resize-379.patch` 与构建源逐字节一致；离线构建及工作台无网络出口检查通过。两台安装相同 379 APK，哈希与构建一致；升级前 378 APK 分别备份在本机 `.nxbridge/controller-120/1372-before-379.apk` 和 `1402-before-379.apk`。

`make check` 通过。当前只支持面键分组，其他按键分组、真实小手、实际游戏内操作和断线故障仍须验收。已知失焦期间松开手柄可能导致返回后的首次按下被拦截，见 [生命周期输入记录](NXB-120-lifecycle-input.md)。
