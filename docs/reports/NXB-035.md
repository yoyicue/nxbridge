# NXB-035：nxnative 离屏帧与 PCM 输出

日期：2026-11-02。任务状态以 backlog 为准。

## 范围与基线

在独立的 nxnative 实验副本接入真实游戏帧和 PCM，保持游戏节奏及有界缓冲；验证媒体 ABI、资源释放、源退出和重启隔离。先在已登录 Mac 会话验证，不推导锁屏、无显示器或未登录能力。[NXB-010](NXB-010.md) 固定了本机实验环境，非官方匹配的 Metal 编译器限制继续适用。

## 源码定位与实验事实

- 引擎的 `nvnQueuePresentTexture` 走 `mtl_present` / `present_enqueue`，无窗口时呈现线程在 `present_now` 无 `CAMetalLayer` 处返回；现有 `DM_NVN_SHOT` 能在返回前同步读回纹理，可用作诊断，不能当作连续帧输出。
- 引擎 `hle_audio.c` 的 `null_sink` 每 5 ms 消费一次游戏 PCM16；`pull_device` 包含声道处理。适配需要保留单消费者和既有释放通知，处理 48 kHz 立体声 PCM16 到媒体 ABI 的 F32 格式转换，避免在音频线程做阻塞 I/O。
- 引擎现有 `DM_PRESENT_SNAP` 的内部纹理环使用 Metal 私有纹理及自身 ticket / shared event 规则，并不是 ABI 的 IOSurface 租约。接入必须另行保证 GPU 写完成、消费者释放后才复用，以及队列有界。
- 无窗口的隔离实例已能渲染菜单并识别独立存档，详见 NXB-010；这些结果还不证明持续导出、音频、播放速度或音画同步。

## 已实现与验证

新增 `adapters/nxnative/pcm_queue.{h,c}`：单生产者 / 单消费者的 20 块暂存队列，接受最多 480 帧的 48 kHz 立体声 PCM16，转换为 F32；队列满时立即丢新块，推进样本计数并在下一成功块标记间断。时间戳按首采样位置计算；队列只在消费者复制后复用槽位。这是进程内暂存组件，还没有接入游戏音频线程、跨进程传输或媒体 ABI 租约。

`clang -std=c11 -Wall -Wextra -Werror -fsanitize=address,undefined -pthread tests/nxnative_pcm_queue.c adapters/nxnative/pcm_queue.c -o .nxbridge/experiment-035/pcm-queue-test` 与该测试可执行文件均通过，覆盖队列满、间断、时间戳、转换和并发单生产者 / 单消费者；`make check`、`make check-rust` 通过。这些检查不证明真实音画输出或音画同步。

随后在独立引擎副本应用 `pcm-probe.patch`，将队列接到第一个立体声静音消费者。`pcm_probe.c` 仅在显式设置 `NXB_PCM_PROBE` 时启用，使用独立线程将最多 8 秒 F32 写入新建的诊断文件；没有改变消费者推进游戏队列的方式。可选 `NXB_PCM_PROBE_SKIP_SECONDS` 跳过启动静音段。这是诊断文件，不是媒体 ABI 或可用的跨进程传输：文件没有间断元数据，初始时间锚也未与实际音频硬件时钟验证。

实机运行隔离存档、脚本操作加载后，纹理诊断图 `pcm-world.png` 显示户外画面；在启动后跳过 45 秒采得 384,000 帧、8 秒、48 kHz 双声道 F32，其中 765,086 / 768,000 个采样非零，峰值 0.068848、RMS 0.003747。前两次各 8 秒的启动 / 菜单采样均为全零，未当作非静音输出成功。日志、截图与原始 PCM 留在 `.nxbridge/experiment-035/`；实例在实验结束后 SIGTERM 退出码为 0。没有进行听感、音画同步或慢消费者下真实进程行为测试；原始文件采样数量也不足以证明没有丢块。

引擎独立副本已应用 `video-probe.patch`，在无窗口的 `present_now` 中调用上游 Metal 4 离屏呈现，输出到最多 6 个 IOSurface-backed 1280×720 BGRA CVPixelBuffer；GPU 完成回调后交给进程内 VideoToolbox 硬件 H.264 编码，编码回调归还槽位，最多两个编码在途。正常 62 秒运行（generation 3）记录 2,924 次申请、2,921 帧编码、3 帧丢弃、0 失败，SIGTERM 后 GPU 排空、VideoToolbox complete 成功且在途为 0。原始 H.264 可由 ffprobe 识别，独立解码出的户外画面位于忽略目录。文件最多写入 64 MiB；这是测试消费者，不是跨进程媒体输出。

将编码回调人为延迟 200 ms 的 generation 2 实验中，18 秒共申请 981 帧，编码 82 帧、丢弃 899 帧、失败 0，采样日志中编码在途最多 2，退出时为 0。实验覆盖慢回调和进程正常退出，尚未覆盖消费者崩溃、GPU 故障及异常重启。

同次正常运行中，视频 trace 的 2,921 条 PTS 严格递增，GPU 完成相对 PTS 的 p50 / p95 为 7.165 / 11.808 ms；音频 trace 有 1,600 个 5 ms 块、PTS 严格递增、未记录间断。两路均使用本机 `CLOCK_MONOTONIC`；音频块 PTS 到最近视频 PTS 的差值中位数 / p95 为 5.745 / 15.657 ms。该数值只是不同周期采样点的距离，不测得内容同步或物理播放延迟；PCM 的观察时刻是软件消费线程读出时间，仍需验证时钟和漂移处理。

在独立进程中进一步验证 Mach 通道：worker 将发送权传给其启动的游戏子进程；GPU 完成后游戏通过 Mach 消息传送 IOSurface 发送权，worker 导入 CVPixelBuffer、硬编码并以会话 ID、代次、帧序号和缓冲 ID 归还租约。控制载荷使用明确的小端字段编码，端口权由 Mach 描述符传送。PCM 通过有界暂存队列和带序号、单调时间戳与间断标记的内联 Mach 消息发送；这是实验协议，尚未实现媒体 ABI 的跨进程注册协议。

2026-11-02 的 60 秒真实 BOTW 隔离实验（generation 9）中，worker 收到并编码 2,682 帧，ffprobe 确认 H.264、1280×720、2,682 帧；源端共申请 2,683 帧、丢弃 1 帧，关闭时未归还数为 0。worker 收到 11,543 个 PCM 块、2,770,320 个立体声帧，其中 3,284,385 个采样非零；记录到两次间断。两端正常退出。原始日志及媒体保存在忽略目录 `.nxbridge/experiment-035/mach-av.*`，不代表客户端播放、内容同步或长期稳定性验收。

视频租约单元测试在真实 Metal / VideoToolbox 下检查了错误会话、错误代次和旧序号释放；同一会话标识的两个正常重启代次，以及一次强制终止源进程后的新代次，分别生成独立帧序列。

补充跨进程故障实验：将 worker 编码回调延迟 1 秒，并在源端日志显示两个编码缓冲在途时强制结束 worker。源继续运行并丢弃无法发送的帧；随后正常结束源进程时日志记录 `outstanding=2`，没有因超时将这两个未归还缓冲标记为可复用。使用相同会话 ID、独立存档和新 generation 12 重启后，worker 收到 657 帧、编码 656 帧、丢弃 1 帧、失败 0，源端退出时未归还数为 0。故障实验日志分别为忽略目录中的 `mach-worker-crash-stall.log` 和 `mach-after-crash.log`。该实验验证本次进程结束前的隔离和独立重启，未验证跨进程消费者重连后复用同一源进程。

worker 现会为每个视频缓冲 ID 保留首个导入的 IOSurface 引用，检查尺寸、行跨度、分配大小、像素格式、同一 ID 的表面身份及编码期间重复使用；编码回调先释放导入的 CVPixelBuffer，再归还源端租约。`mach_abi.h` 将经验证的 Mach 视频字段及导入表面几何映射为共用 C ABI 的视频缓冲和帧描述符；内联 PCM 被复制到 worker 内固定缓冲后映射为音频描述符，并检查时间戳与样本位置的连续关系。generation 15 的 12 秒隔离实测收到 615 个视频帧、编码 614 个、丢弃 1 个，收到 2,136 个 PCM 块并记录 1 次间断，失败为 0，源退出时未归还数为 0。此次音频均为启动画面的静音，非静音证据仍以前述 generation 9 为准。

映射视频描述符时将颜色按 BT.709 暂作实验假设，尚未验证游戏实际色彩传递；不能据此声称色彩元数据已验收。PCM 是内联消息复制到 worker 本地缓冲，不是跨进程共享 PCM 缓冲注册。generation 15 时视频还采用首次帧隐式登记；后续已增加独立注册确认，见下文。

后续修复音频间断重锚后的取整：现在从新的首样本计算后续时间戳，避免任意块长度下与 ABI 公式相差 1 ns；单样本长度的重锚回归测试通过。worker 对本地 PCM 缓冲执行注册、占用和同步释放检查，并严格核对连续时间戳。视频源增加至多一个 GPU 写入中的缓冲约束，满时直接丢帧而不阻塞呈现线程；真实 Metal 测试覆盖错误会话、代次和过期完成消息。generation 18 的短时真实游戏运行中，worker 收到并编码 570 帧，收到及释放 1,987 个 PCM 块，失败为 0，源端退出时未归还数为 0。该次为启动静音场景，非同步验收。

实验 Mach 协议增加了独立视频注册和确认：源只在对应会话、代次和缓冲的确认后发布帧；可对同一表面的重复注册幂等回复，拒绝冲突注册。generation 19 实测两个缓冲完成注册、570 帧编码，退出无未归还帧；generation 20 故意返回错误会话和代次的确认，源未发布任何帧。释放消息现明确携带编码、丢弃或失败结果。generation 21 正常实测编码 625 帧；generation 24 人为延迟 worker 编码回调 200 ms，六个缓冲均注册，worker 排队满时记录按序淘汰较旧帧，编码 55 帧、丢弃 559 帧，退出时源端未归还数为 0。Mach 内核通信队列满时仍会拒绝新帧，完整策略及限制见 [实验协议](../mach-media-v1.md)。

`tests/nxnative_mach_wire.c` 检查本地协议的固定字节序及字段往返；PCM 队列的并发测试、带清理的独立 checkout 补丁应用检查和 `make check` 通过。故障注入只结束实验 worker 与按 PID、启动时间核对的实验游戏子进程；现无本任务游戏或 worker 进程运行。

同一引擎、游戏、隔离存档和固定户外静止场景的短时对照：各预热约 65 秒，按游戏 `@frame_ms` 记录各约 90 秒。窗口 / 物理 AudioUnit（静音）为 3,185 帧、35.309 FPS、帧间隔 p50 / p95 / p99 为 33.010 / 34.281 / 34.813 ms；无窗口 / Mach 离屏硬编 / 定时音频消费者为 3,015 帧、33.391 FPS、33.245 / 34.286 / 34.804 ms。两次采样均无超过 100 ms 的帧间隔；日志内游戏时间 / 实际时间分别约 1.001–1.002 和 1.000。两次截图确认同一户外场景。引擎使用游戏 profile 的自适应 60 FPS 目标而非锁定 30 FPS；窗口组不进行视频编码，离屏组编码 1280×720 H.264，故只作迁移影响的探索性对照，不是同编码条件的正式基线或 10 分钟重复验收。原始 TSV、进程日志和起止帧保存在忽略目录 `timing-window.*`、`timing-offscreen.*`。

对 generation 9 的编码文件调用 ffprobe 得到 `color_range`、`color_space`、`color_transfer` 和 `color_primaries` 均为 unknown。引擎上游呈现代码注释表明其输出 swapchain 原始字节；该证据不能证明 BT.709，实验描述符中的色彩值仍是未验证假设。

## 2026-11-03 无 Pad 回归与修复

修复三处离线发现的契约问题：Rust 音频租约现在拒绝未标间断的序号跳变；Mach worker 对仍被持有的相同租约的重复帧不发送提前释放；worker 向 Rust 私有数据报发送 PCM 失败后，在下一次成功发送的块标记间断，Rust 对标记进行校验与限量记录。GameStream 下游当前仍只有 PCM 数据，不接收 PTS 或间断标志，未实现丢失补偿或音频时钟恢复。

修复前回归测试分别复现了音频跳号被接受、重复帧导致提前释放、音频数据报丢失后缺少间断标志；修复后通过。`tests/nxnative_mach_duplicate.m` 使用实际 Mach 回复端口及 IOSurface 待编码对象；`tests/nxnative_audio_backpressure.m` 填满真实 Unix 数据报缓冲并检验下一成功块。新增 `make check-native-media`，涵盖上述测试、PCM 队列 AddressSanitizer / UndefinedBehaviorSanitizer、Mach 线协议和跨进程 IOSurface 传递；另通过 `cargo test --workspace --offline`、`make check` 和 `make check-rust`。重建 worker 以 `/usr/bin/true` 子进程完成初始化与回收冒烟检查，按设计因未收到帧而退出码为 1；这不是游戏媒体测试。没有连接 Pad 或运行真实游戏；GPU 编码回调下的重复消息、实际音画同步与丢块补偿尚未验证。

已重建 Rust 服务程序及实验 Mach worker。2026-11-03 根据用户要求核实游戏和 worker 均未运行后，逐个重启两个服务；HTTP `serverinfo` 均返回 200、空闲状态，主机身份与端口组保持原配置。后续游戏会话使用重建的 worker；原 worker 的本机备份保留在忽略的实验目录。服务重启后尚无 Pad 验证，未动玩家存档，任务仍为进行中。
