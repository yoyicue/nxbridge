# NXB-112：Pad 小手触屏布局

日期：2026-11-08。任务状态以 backlog 为准。

## 目标与范围

在已安装的 NXBridge Pad 320 基础上，改善两台相同型号 2560×1600 Pad 的触屏布局。假设为横屏双手握持；舒适区尚未由实际使用者验证。保留 Switch 面键方向、Moonlight 原生 GameStream 输入、既有布局编辑和保存配置；不主动修改或恢复游戏存档，也不改变服务端输入协议。测试时游戏可能正常写入隔离存档。

## 变更

322 将面键从 6 格增至 7 格，将摇杆从 16 格增至 17 格；左摇杆和十字键位置分开，肩键与面键分开，菜单键向上移动。方向键由四个圆形改为带箭头的方形十字方向区；按下高亮仍由现有触控路径提供。沿用已有的移动、缩放和透明度设置；没有新增浮动摇杆、布局预设或游戏状态识别。面积、位置和实际握持舒适度尚待人工评价。

源代码补丁为 `adapters/input/moonlight-pad-layout-322.patch`，由 `apply_pad_layout_322.py` 应用于 320 实验树；上游修订与 GPL 来源见 `adapters/input/NOTICE.md`。增量补丁不是完整、干净环境可复现的客户端构建流程。

## 验证证据

- 在独立实验源码副本运行 `./gradlew --offline :app:assembleNonRootDebug` 构建成功。将增量补丁重放到 320 副本后，与实际构建涉及的三个文件逐字节一致。
- 通过设备各自的 xpad2 0.7.5 受管安装升级：两台 `com.limelight.debug` 的 PackageManager 均显示 versionCode 322。各自原 320 APK 已备份；安装前两台均无 `OSC.xml` 自定义布局文件。升级未清除应用数据或配对信息。
- 第一轮 321 实机截图发现 X 与 ZR 重叠，已调整肩键纵向位置并升级到 322。322 在第二台 BOTW 标题画面截图显示 X / ZR 已分离，方向键为独立上下左右；第一台在连接界面也显示相同的新布局。截图保存在本机忽略目录 `.nxbridge/pad-layout-321-backup/`。
- 第二台通过 ADB 模拟触摸，每次持续约 350 ms：上、左、右、下分别在游戏输入跟踪中出现 `8192`、`4096`、`16384`、`32768`，各自释放后均为 0。一次双指模拟同时推左摇杆并按 B，游戏侧记录 `131074 -222 32765 0 0`，随后回零。ADB 只用于模拟 Pad 触摸；传输仍是原生 GameStream 控制通道。轨迹与探针保存在同一忽略目录。
- 第一台的原服务地址从当前 Pad 网络不可达。临时切到另一可达地址后 HTTP 发现成功、旧配对身份保留，但串流控制连接报 error 11，故无法验证该设备的游戏输入。Mac 到该 Pad 的路由指向另一网卡，同网段地址由多张网卡持有；这是需要进一步排查的线索，不能断言唯一原因。原服务绑定已恢复，Pad 当前网络未改。手动添加的新地址保留在原主机记录中。
- 第一台临时切换输入法以输入测试地址后，已恢复搜狗并禁用临时启用的 Latin IME。两台安装临时 APK 和第二台临时探针均已删除。两份隔离存档在首次启动前备份并逐文件校验；第二台 322 会话启动前再次备份。
- `make check` 及 `make check-release-content` 通过；发布内容扫描是启发式检查，不替代授权和实际发行物审核。

## 限制和交接

第二台的模拟输入不是手指真实握持或所有组合的验收；第一台串流输入未验证。未实测小手连续游玩、误触率、HUD 遮挡、触觉反馈或端到端延迟；不声称布局已达到最佳手感。测试结束两台客户端游戏会话均已停止，对应 worker 和游戏进程已退出。第一路原实验服务以 PID 22919、第二路以 PID 35156 空闲运行；操作前重新核对 PID、命令和启动时间。

下一步先排查第一台与第一路服务的双网卡路由，完成该台实际按键和多点组合验证；再请使用者握持试玩，依据误触、跨度、HUD 遮挡调整默认布局。若需恢复 320，可使用忽略目录中对应设备的旧 APK，按该设备的受管安装器能力验证是否支持降级；不要卸载应用或清除数据来绕过降级限制。

## 2026-11-08：浮动摇杆与独立操作区域

用户反馈固定圆心在大平板上仍难够到。324 版默认将左右摇杆改为浮动模式：静止时隐藏，在各自的操作区域内按下时以触点为中心显示摇杆；移动映射为原有 GameStream 摇杆轴，松开或取消时归零。操作区域默认位于屏幕左右两侧；固定控件位于区域上层，按键优先。左上角齿轮依次切换移动区域、缩放区域和保存退出；编辑时显示区域边框。应用设置的“浮动摇杆”可关闭以使用固定摇杆，固定和浮动摇杆各自保存区域，其他按钮仍沿用原布局数据。用户自定义布局优先，未提供自动适配或按游戏分别保存。

在独立 322 副本上构建；改动以 `adapters/input/moonlight-pad-layout-324.patch` 和 `apply_pad_layout_324.py` 保存，补丁重放后八个涉及文件与构建树一致。`FloatingStickMathTest` 覆盖轴方向、死区、斜向和限幅；`make check` 及发布内容扫描通过。两台设备安装前各自的 322 APK 已备份，当时均没有保存的 `OSC.xml`；安装均经 xpad2 0.7.5，PackageManager 核对 versionCode 324。

第二台通过 323 实机游戏测试：空闲截图无摇杆，触摸时摇杆出现在触点；一次双指左摇杆加 B、右摇杆单轴、上方向、X、ZR 均有游戏输入记录，释放归零。编辑器实测区域边框、拖动、缩放并保存到独立键；测试产生的布局文件在结束后移除，恢复为该台测试前的无自定义布局。模拟 `ACTION_CANCEL` 及一次推住摇杆后强制断开时，输入跟踪均出现非零后归零；不能外推所有断线故障。323 的设置入口被旧屏幕手柄开关错误禁用，324 去除该依赖；第二台实际打开该设置、关闭浮动模式并看到固定摇杆，再开启浮动模式，一次 324 左摇杆加 B 输入及归零成功。323 与 324 的差异仅为设置依赖和版本号。

两台当前均安装 324；第二台保留显式浮动模式开启，第一台采用默认开启。第一台由于前述网络问题未完成游戏内浮动输入测试。测试期间的第二台隔离存档已分别备份并逐文件校验，测试探针和临时 APK 已删除；游戏与 worker 退出，原两路服务保持空闲。原始截图、输入轨迹及备份保存在 `.nxbridge/pad-layout-323-backup/`。尚需第一台恢复串流后的输入验证及真实小手握持试用；这次没有独立验收画面延迟或所有多点组合。
