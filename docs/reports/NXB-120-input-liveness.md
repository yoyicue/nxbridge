# 输入失联时序实验

日期：2026-11-09。实验服务使用与当前 GameStream 输入逻辑相同的隔离源码副本，额外将控制 UDP 绑定到本机回环并记录认证消息时刻；Mac 上的单会话代理转发该连接并在指定时刻只丢弃客户端到服务端的控制数据。音视频未经过代理。游戏使用固定 nxnative 修订 `b8d16169c5fb7a3c6a936a950e294b1df4680551` 的隔离构建，采样记录额外启用单调时钟。诊断埋点和代理会带来未量化的扰动。

环境：Apple M4、16 GiB、macOS 26.5；1372 Pad 为 TALIH-PD2、Android 13、客户端 357，经 Wi-Fi 连接；Mac 到该设备的路由使用 en0。BOTW 构建 `v1114112`，游戏启动后画面出现阶段（未截图确认具体场景），离屏 nxnative / Mach 帧源，1280×720、30 FPS H.264、5 Mbps 串流。观察的是主机上从代理开始丢包到游戏输入接口采样归零，不是 input-to-photon，也不是拔网或关闭 Wi-Fi 的精确时间。客户端按住通过 ADB 触摸生成。

| 条件 | 样本 | 丢包开始到游戏采样归零 |
| --- | ---: | --- |
| 旧 250 ms 静默阈值，故障时刻不对齐心跳 | 8 | 170.3–236.3 ms |
| 旧 250 ms 阈值，刚收到认证消息后故障 | 4 | 249.4–261.6 ms；其中 3 次超过 250 ms |
| 候选 215 ms 阈值，刚收到认证消息后故障 | 4 | 216.6–230.5 ms |

旧阈值的认证消息到 watchdog 触发约 250.1–258.8 ms，触发到游戏采样还需时间。候选版本将控制循环的等待限制在 watchdog 剩余时间内，并把阈值设为 215 ms，为后续环节留出预算。这个选择减少对网络抖动的容忍，并不保证所有采样频率或网络都能在 250 ms 内归零。

候选版本另做 4 次约 140 ms 和 4 次约 190 ms 的短时单向丢包，按住期间未观察到误中和；后者实际认证消息间隔约 193.0–204.6 ms。另在部署后的 1402 实际 BOTW 会话中保持 ZL 10 秒，其中 6 秒连续观察没有误中和，松开后游戏采样归零。这些短样本无法证明长期无线稳定、实体手柄或弱网表现。全部游戏存档在各自实验前备份，测试前后各 20 个文件 SHA-256 一致。

原始样本、游戏采样、服务时序日志与实验 JSON 保存在本机忽略目录 `.nxbridge/controller-120/timing-*`，1402 部署回归记录为 `watchdog-215-1402-trace.txt`。一次最初运行在输入接收器启动后过早检查视频，未采集到有效时序样本，已单独保留结果；随后修正等待首帧的条件。隔离测试结束后恢复原游戏预热设置及正常服务；随后两路本机实验服务切换到 215 ms 版本。先前 250 ms 二进制备份为 `.nxbridge/controller-120/server-250-before-watchdog`，两路会话及子进程均退出后，可用 `.nxbridge/controller-120/rollback-watchdog-215.py` 恢复；操作前仍需核对当前会话。

`tests/control_udp_fault_proxy.py` 是只用于显式隔离实验的单客户端代理，不记录数据内容；`tests/control_udp_fault_proxy_test.py` 验证转发、丢弃和恢复。本仓库新版接收器仅在同时设置 `NXBRIDGE_INPUT_TRACE` 和 `NXBRIDGE_INPUT_TRACE_MONOTONIC=1` 时以 `M <CLOCK_MONOTONIC 纳秒> <buttons> <四轴>` 记录变化；旧格式默认保持不变。此格式已编入隔离测试引擎，当前日常游戏引擎尚未更新。采样记录可能包含操作行为，只应在诊断时显式启用。
