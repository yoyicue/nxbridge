## 修复

## 呈现层短时探索

使用相同 1372、同一客户端和合成音画服务，客户端配置 1280×720 / 30 FPS / 5 Mbps；本次没有独立记录协商结果。分别关闭和开启虚拟按钮，每组约 18 秒，每秒通过 `uinput` 模拟一次 L 键按放。合成服务日志在两组各记录 18 次按下和释放。内容来自同一会运动并显示帧号的合成源，但两次开始于不同帧号；仅一组顺序运行，未重复或随机化，不能排除网络、热状态和系统调度差异。截图仅在采样前使用，未持续读取屏幕。

利用 `SurfaceFlinger --latency` 的视频层第二列呈现时间，周期性读取并按时间戳去重；各相邻快照均有重叠，无明显环形缓冲缺口。设备报告显示刷新周期 16.67 ms。表中为视频层呈现，不是游戏引擎帧率，也不是输入延迟：

| 虚拟按钮 | 呈现帧数 / 区间 | 呈现 FPS | 间隔 p50 / p95 / p99 |
| --- | ---: | ---: | ---: |
| 关闭 | 524 / 523 | 28.97 | 33.34 / 50.00 / 50.02 ms |
| 开启 | 525 / 524 | 29.06 | 33.34 / 50.00 / 66.66 ms |

每组只是一次短样本，p95 / p99 使用最近秩次；上述差异不证明虚拟按钮造成或没有造成性能变化。物理控制器模拟不触发虚拟按钮高亮，属于手柄 UI 闲置场景；`gfxinfo` 重置后关闭组记录 0 帧、开启组记录 1 帧，样本不足，不能使用其百分位数估算 UI 绘制开销。无 UI 激活场景、客户端输入 A/B 或 input-to-photon 结果，因此 VC-13 尚未验收。

BOTW 也做了相同的开启 / 关闭短时尝试，但两次标题背景不同，不能作为公平的游戏性能对照；不从这组数据推导 UI 影响。原始数据和截图在本机忽略目录 `.nxbridge/controller-120/ui-ab-*`、`toggle366-*.png`，分析程序 `tests/surface_present_analysis.py` 处理快照缺口、无效时间和去重，其测试通过。

测试前备份的 1372 存档 20 个文件在测试后 SHA-256 不变；两路原服务均已恢复空闲。临时游戏会话、合成服务和模拟手柄已退出；原偏好文件逐字节恢复。此前 365 APK 分别保存在本机 `.nxbridge/controller-120/1402-before-366.apk`、`1372-before-366.apk`。离线 Gradle 构建、补丁在记录的 365 源文件上应用检查、工作台传输隔离检查及 `make check` 通过。真实物理手柄、实际双手握持、主动触屏时 UI 绘制和游戏实战性能仍需验收。
