# NXB-141 · S2Arm 离屏呈现和管线预热

2026-11-18 在 M4 Mac mini（16 GiB、macOS 和 SDK 26.5、.NET SDK 10.0.403）适配并构建了 S2Arm 候选 `75852d41e1cc2f78a7c61195dcf4bb6d4543fd5d`。完整修订和对应补丁已登记，使用 `adapters/s2arm/prepare.py --revision` 可重放。另从干净源码重放并核对了实际编译目录中清单所列文件的摘要。[实验锁](../../config/s2arm-experiment-lock.json)

## 实现

- 将无窗口分支接到现有 IOSurface 输出。上游先准备裁切和实际纹理坐标，NXBridge 再使用对应的 Metal 队列编码和等待 GPU 完成。提前退出和帧槽耗尽共用等待逻辑，防止较新的跳过帧提前推进较旧源纹理的释放栅栏。[呈现补丁](../../adapters/s2arm/integration-75852d4.patch)
- 保留按游戏构建摘要启用的 RG11B10Float 纹理拷贝预热。预热调用与真实拷贝共用管线缓存，在编码 GPU 工作之前返回。准备失败时首次实际拷贝仍可重试。[预热补丁](../../adapters/s2arm/prewarm-75852d4.patch)
- 复用新版上游的平方和 sRGB 解码管线后台构建，以及种子清单缺失时继续预热本机记录的逻辑。旧版修订仍选择其各自的集成和预热补丁。

## 验证

| 检查 | 结果 |
| --- | --- |
| Metal 3 和 4 离屏呈现 | 各通过普通输出、帧槽耗尽和裁切，合计 6 组。每组 14 帧硬件 H.264 解码像素通过。延迟约 300 ms 的生产者事件完成后才释放源纹理；两组帧槽耗尽各出现一次预期丢弃。 |
| GPU 反馈和缓存边界 | 24 项 GPU 反馈检查、6 项预热清单路径检查和 3 项归档清理隔离检查通过。 |
| tensor 后台预热 | 从候选源码提取上游预热函数，在真实 Metal 设备上验证了启用条件、两条管线的异步构建和读取时复用。 |
| OoT 首次启动 | 现有游戏构建通过 shader 链校验。从经校验的 1402 存档备份读到林克房间并走出门进入森林。纹理拷贝预热 `ready=1`，候选从路线文本记录重新编译 975 条管线。 |
| OoT 重启 | 出现启动画面，纹理拷贝预热 `ready=1`，候选自己的归档命中 975 条，现编 0 条。两轮均使用 Metal 4 的上游默认独立编码线程。 |

两轮只复用同游戏身份的文本管线记录作为起点，二进制归档均由候选生成。Mach worker 分别编码了 2,646 帧和 529 帧，失败和未释放帧均为 0，收到非静音 PCM。首次读档到出门最长源画面间隔 825 ms，共 6 次超过 100 ms，音频源记录 34 次间断。最长帧的提交与呈现合计 8.4 ms，未记录新管线、着色器库或纹理上传。两次采样覆盖不同场景，尚无相同路线的性能对照或 Pad 端验收。

`make check`、`make check-native-media` 及准备、启动、缓存的 33 项 Python 测试通过。两个实验实例退出码为 0，备份中的 32 个文件与原摘要相符。两台日常入口仍使用 `d5435c3`。原始构建、编码和逐帧证据与 `experiment.json` 保存在本机 NXBridge 临时根目录的 `nxb141-75852d4/`。独立源码和二进制目录记录在本机忽略文件 `.nxbridge/s2arm-75852-study`。
