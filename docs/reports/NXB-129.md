# NXB-129：时之笛单路卡顿调查

日期：2026-11-10。状态以 backlog 为准。执行者：Codex。

## 目标与范围

用户确认单台串流卡到基本不可用发生在 20:35–20:40，优先排查单路严重停顿。以该次 1402 会话的存档与缓存副本做隔离检查，保留原始玩家存档和日常服务的回退入口。

## 现有证据

- 1402 服务日志最后一次游戏会话为本地时间 20:35:49 至 20:40:37，另一服务的最后会话在 20:01 前结束。用户确认这是所报告的时段；该会话使用时之笛 S2Arm 离屏路径和新档工作目录。
- 该会话 worker 记录源时间戳间隔超过 100 ms 共 52 次，最长 13,236 ms。S2Arm 长帧记录对应一次 13,236 ms 的整帧，其中 submit + present 为 13,231 ms，记录到新建 24 个 pipeline 和 32 个 shader library；另一次整帧约 9,996 ms，记录新建 34 个 pipeline 和 35 个 shader library。并行编译各项累计耗时不能简单相加当作关键路径。源间隔属于游戏到 worker，不是 Pad 显示 FPS 或网络延迟。
- 该会话结束汇总记录 worker 编码失败 0、VideoToolbox 回调最大 49.472 ms；这不足以排除 Wi-Fi、客户端解码或其他时段的问题。游戏运行时编译与长帧同时出现，是优先追查线索，不足以独立证明完整因果。
- 已知游戏构建使用 runtime-only 路径，完整离线构建此前因磁盘余量中断。现有持久缓存与预热仍无法覆盖所有首次出现的 shader / pipeline，见 [NXB-128](NXB-128.md) 与 [适配说明](../../adapters/s2arm/README.md)。
- 卡顿会话启动时已读取 2,372 行记录、1,132 条现有归档，预热结束时仍新增了管线。13.2 秒帧的 shader 组合已在会话结束后的 `pso_user.tsv` 内；该管线归档当时尚未在批次索引中。上游源码表明游玩期间遇到的管线先记录，后续预热才生成归档。
- 隔离启动复制了该会话结束后的存档和完整缓存，使用原游戏构建及引擎、Mach worker、VideoToolbox；未连接 Pad，也未操作进入发生卡顿的场景。90.6 秒后正常退出，预热读取 2,820 行，命中 1,150 条归档并新编 199 条；最慢帧涉及的管线及该帧另一个等待管线均出现在新归档批次索引中。预热约 60.2 秒完成，15 秒后剩余 869 项转后台。这验证新记录可在下一次启动产生归档，**不验证卡顿路线改善或下次启动时此管线一定在遇到前编好**。

## 验证与限制

确认事故会话后执行一次有界隔离启动。实验采样最低磁盘余量约 18.21 GiB、系统 swap 最高约 4.35 GiB、游戏足迹最高约 4.14 GiB；这是未进入现场场景的样本，不能比较游戏性能。worker 记录最长源间隔 84.341 ms，未反映客户端显示。隔离游戏及 worker 已退出，退出码 0；输出位于 `.nxbridge/experiment-128/nxb129-replay-20261110/`，其中缓存和存档副本均不可作为玩家原件删除。上游构建脚本记录完整 shader 批处理临时数据可能达数十 GB；本机可用空间不足以安全直接重跑，网络工作盘先前还出现 I/O 停滞。

`cargo test -p nxbridge-gamestream --offline` 通过 19 项，包括延迟连接丢弃旧输入、断线中和与恢复时限；S2Arm 启动测试 15 项和 `make check` 通过。变更过的两个 Rust 文件单独 `rustfmt --check` 通过；`cargo fmt --all -- --check` 未通过，输出涉及 vendor/moonshine-core 等已有格式差异，未改写第三方代码。这些检查不代表游戏性能已通过。
