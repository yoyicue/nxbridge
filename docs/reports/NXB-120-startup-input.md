# NXB-120：加载期间的手柄输入

日期：2026-11-09。任务状态以 `tasks/backlog.json` 为准。

## 问题与修改

383 加载页会隐藏触屏控件，但没有屏蔽实体手柄路径。1372 使用临时 Android 虚拟手柄及延迟约 6 秒出画的合成服务，输入桥已经就绪而首帧尚未产生时，一次 L 按放仍被桥记录为 `0100 → 0000`。这是加载页覆盖画面但手柄仍可能操作的问题，与此前重连启动阶段的触屏点击未观察到不能直接认定为同一原因。

384 在 Game 创建连接前设置独立的启动输入屏蔽，设置时不向尚未连接的原生桥发送数据；加载页结束时才解除这一屏蔽。它与编辑和生命周期屏蔽分别计算，解除其中一项不会解除其他仍有效的屏蔽。启动期间的旧手柄按住须释放后再接受新按下。

跨加载按住测试又发现：释放已被客户端收到、所有输入回中后，未分配手柄的中和包可能在通知来源仲裁前提前返回，使第一次新按下仍被丢弃。仅用于诊断的 385 确认了该顺序；386 在全中和后先重新允许物理来源认领，再走原有返回逻辑。它不消除另一种情况：如果失焦期间的物理释放事件根本没有送到应用，返回后的第一次按下仍可能需要松开重按，见 [生命周期输入记录](NXB-120-lifecycle-input.md)。
