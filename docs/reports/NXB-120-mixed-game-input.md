# NXB-120：双游戏标题画面输入隔离试验

日期：2026-11-09。任务状态以 `tasks/backlog.json` 为准。

## 环境与范围

Mac M4、16 GiB、macOS 26.5；两台 Android 13 Pad 均为 NXBridge Pad 357，经各自 Wi-Fi 连接 GameStream，USB ADB 仅用于注入触摸和临时断网。1402 使用《王国之泪》，1372 使用《旷野之息》1.9.0；两路使用独立服务、游戏进程和存档。两份引擎工作副本基于 nxnative `b8d16169c5fb7a3c6a936a950e294b1df4680551`，带本项目输入补丁；服务端使用当前部署的 215 ms 输入静默阈值。游戏和输入桥的具体配置为本机实验配置，不代表通用安装流程。

两路先后启动，截图确认同时进入各自游戏的中文标题画面。系统 `memory_pressure -Q` 报告的 system-wide memory free percentage：启动前 62%、第一路出画后 35%、两路标题画面约 27%、退出并恢复后 60%。这些是特定时刻的系统整体快照，不是单会话内存占用、压力等级或容量测试；没有采集 FPS、输入到画面延迟、音频隔离或实际游玩场景。

## 操作与结果

- 两边均空闲、无子进程时，对两份存档做独立备份并逐文件 SHA-256 校验；分别为 17 和 20 个文件。测试中未进入游戏存档。退出后再次校验，全部相同。
- 单击 1402 的 ZL，1402 接收器出现 `256 → 0`，1372 接收器无新增事件；单击 1372 的 ZR，1372 出现 `512 → 0`，1402 无新增事件。
- 1372 保持 ZR 时临时关闭其 Wi-Fi；在触摸仍保持期间，1372 接收器从 `512` 回到 `0`。故障期间 1402 的 ZL 仍产生 `256 → 0`；1372 恢复 Wi-Fi 后一次新 ZR 又产生 `512 → 0`。观察过程中 1372 的 Wi-Fi 开关恢复到原先的开启状态，且重新连网。
- 从执行关闭 Wi-Fi 命令到脚本观察到中和约 263 ms；这包含 ADB 命令和轮询开销，关闭网络的实际生效时刻未知，不能作为 250 ms 失联目标的同钟计时验收。精确控制通道故障时序与局限见 [输入失联时序实验](NXB-120-input-liveness.md)。

测试截图、两路输入轨迹和断网记录分别保存在本机忽略目录 `.nxbridge/controller-120/mixed-totk-video.png`、`mixed-botw-video.png`、`mixed-1402.trace`、`mixed-1372.trace` 和 `mixed-fault-result.json`；不包含在发行内容中。本次只覆盖一次短时 Wi-Fi 故障、两种按钮及各自标题界面，不能外推到所有断线、物理手柄、多游戏游玩或持续稳定性。

## 恢复

两台客户端正常退出游戏，已确认 worker 和游戏子进程退出后恢复原两路服务；1402 和 1372 的服务 PID 分别为 5268 和 5270，两个服务均报告空闲、无子进程。PID 仅为本次记录，后续操作须重新校验进程身份。两份存档备份留在本机忽略目录 `.nxbridge/controller-120/mixed-totk-save-before` 和 `mixed-botw-save-before`；第二路的临时关闭 PSO 预热设置随测试服务退出，原启动配置已恢复。并发容量仍未知。
