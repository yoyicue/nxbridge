# NXB-137：上游更新与兼容验证

日期：2026-11-13。状态：进行中。执行者：codex。

## 目标与范围

以精确修订评估 S2Arm、nxnative / NX2Apple、Sunshine 和 Moonshine 对现有 Mac 游戏与串流链路的影响；在隔离环境复用适用改动，不覆盖日常引擎、配置或玩家存档。上游研究快照与实际运行锁分别保存在 `config/upstreams.json`、`config/s2arm-experiment-lock.json` 和 `config/nxb010-experiment-lock.json`。

## 已完成的变更与证据

### S2Arm

候选固定到 [`d5435c3cf2a4bbdd0e36ed3cf21440ee714efa0b`](https://github.com/jhaizhou-ops/S2Arm/commit/d5435c3cf2a4bbdd0e36ed3cf21440ee714efa0b)。原 `069b187` 补丁能机械应用，但新上游将帧 GPU 安全策略改为单帧超 1 秒警告、连续三帧各超 3 秒后交互暂停，旧补丁因此引用了已移除的常量并编译失败。针对无交互恢复界面的 NXBridge，独立补丁保留既有 1 秒安全停止、异常反馈保守上界和队列去重；不把机械应用成功当作兼容。该策略可能较上游更早停止慢帧，须记录而非宣称体验改善。

隔离候选的图形库和 Host 构建成功；GPU 合成反馈 24 项、Metal 3 / Metal 4 离屏事件依赖和帧槽压力、H.264 编码解码以及 73 项音频接口测试通过。OoT 构建的上游链号检查通过，不等于全部游戏内容或时序兼容。原始产物与日志位于本机缓存 `~/Library/Caches/NXBridge/upstream-audit-20261113/`，游戏构建、存档及机器数据不进入提交。

以 1402 的隔离房间存档与独立缓存重走标题至森林：10 个自动截图检查点通过，地面后自动移动不足，手动补移动并按 A 后进入莎莉亚对话。暖缓存预热记录、截图与服务日志保存在候选缓存目录。该轮最终源画面间隔累计超过 100 ms 11 次（包含关停统计），最长 674.792 ms；对应长帧 GPU 性能值为未知，记录 10 次首次纹理上传 4.6 MB / 25.1 ms、提交与呈现 131.6 ms。日志还记录 41 次音频源间断，尾部 PCM 块全部释放、bridge_other 为 0。截图轮询、手动补动作、最初同时有编译负载；该样本不是严格性能对照，不证明稳定帧率、游戏速度或音画同步，也不表明卡顿修复。隔离会话退出后原服务恢复、原玩家存档哈希未变。

上游 [`881aa2c`](https://github.com/jhaizhou-ops/S2Arm/commit/881aa2ce3fb52b579c032f4f0339b39f12a942a7) 等提交修改 `graphics/nvn/replay/` 中的资源初始化与诊断。本次实际构建的 Mac `libnvn.a` 包含 `nvn_mtl.m.o`，没有 `rp_*.o` 回放层对象；这些改动不能作为本次 Mac OoT 性能改善的依据，是否移植应另做架构与语义验证。

### Moonshine

当前集成核心来自 rgsp-cast 的 Moonshine v0.15 派生版本，不直接覆盖为 `7e214670e855f6faa6e01f02b849c27adb4a9161`。选择性适配上游 RTSP 修复：未完成请求累计不超过 64 KiB，单次请求在 15 秒绝对期限内接收完；以字节缓存跨读取片段，拒绝零帧率、越界视频包大小及编码器码率整数溢出；packetizer 直接调用也校验包大小。来源和授权见 `vendor/moonshine-core/NXBRIDGE-NOTICE.md`。

本机 RTSP 服务测试使用独立回环端口与测试会话，跨 UTF-8 字节分片发送 OPTIONS，验证成功响应；超过 64 KiB 的未完成请求被拒绝，ANNOUNCE 测试正常参数成功、三个非法参数被拒绝。大小上限、期限、溢出及 packetizer 的边界测试通过。`cargo test --offline --manifest-path vendor/moonshine-core/Cargo.toml`：61 项通过、2 项忽略，另有 1 项协议表面测试通过。`make check-rust`、合成音画文件的生成和解码通过；合成文件本身不是 Moonlight 会话。

另外以带本次代码的独立 GameStream 构建、隔离存档与缓存副本在 1402 实测：Moonlight 正常连接，标题、选档和确认输入的四个截图检查点通过，随后读取房间截图通过。该短测沿用新 S2Arm 候选，不能证明其他游戏、长期连接或音画同步。测试后原服务恢复、原玩家存档哈希未变；两次测试复制的配对状态已从缓存清理。该轮测试时源码与新服务二进制尚未部署到日常入口；后续部署见下。

### nxnative / NX2Apple

隔离检出 nxnative [`8d44aaf8f3a59eb0e0f63ced14b3f7f26e903484`](https://github.com/seedds/nxnative/commit/8d44aaf8f3a59eb0e0f63ced14b3f7f26e903484) 和 NX2Apple [v1.4.0](https://github.com/LNPANDY/NX2Apple/releases/tag/v1.4.0)（`97ba00eb64e60037e173856197dce291b38bb3b3`）。现有三份 nxnative PCM / 视频 / 输入补丁分别在 `hle_audio.c`、`Makefile` / `hle_lifecycle.c` 和 `hle_hid.c` 应用检查失败。已按新源码生成 [候选补丁](../../adapters/nxnative/integration-8d44aaf.patch)，并用准备脚本从精确修订重放；BOTW 游戏配置下，音频、输入、退出三个 C 文件语法检查通过。当前 macOS 26.5 / SDK 26.5 缺少新版 MetalFX 的 content / output offset 属性，`nvn_mtl.m` 语法检查失败；选中的命令行工具缺少 `metal`，也没有完整 Xcode 可用。尚未完整构建或运行新版，因此不能用于现有 BOTW / TOTK 会话。新版 NX2Apple 宣布其引擎不再依赖 .NET；这一结论不能外推到本项目 S2Arm。

### Sunshine

主分支 `f1868133b2308a1486624fc9d561b9e58cdf8cb4` 的新预发布版本包括 [macOS 手柄支持](https://github.com/SunshineStream/Sunshine/pull/5807)。[libvirtualhid 官方说明](https://github.com/LizardByte/libvirtualhid)指出 Mac 虚拟手柄需要有许可证的签名 Broker 和 Apple entitlement；库与 Broker 的许可不同。它可作为单会话原生手柄对照，但没有证明多玩家按会话隔离，也未安装、购买或切换服务。

## 限制与后续

不同上游的变更、编译与合成测试不代表真实游戏的流畅度、完整音画同步或并发容量已经通过。新版 nxnative 要先重新适配 PCM、帧释放和按会话输入；Sunshine 需另行评估许可证、安装及隔离；Moonshine 未整体升级，后续仍需真实客户端回归与协议模糊测试。S2Arm 仍有明显长帧和音频间断；继续分析资源加载及提交等待，并按存档和场景做受控对照。该轮结束后 1402 日常服务恢复；1372 未操作。独立候选运行时和游戏缓存保留在可清理的缓存目录，正式存档和配置保留在持久目录。

部署后用实际持久运行时、沙箱、GameStream 二进制及独立存档 / 缓存副本，在 1402 验证 OoT 标题、选档、确认和房间读档；两个内部管线预热成功，归档命中 1,431 条、现编 0。该短测记录最长源间隔 749.027 ms、5 次大于 100 ms；音频源记录 9 次间断，worker 记录 13 次 bridge_full / bridge_dropped，尾部其他桥接错误为 0。不能据此认定流畅度、音画同步或关停音频连续性通过。
