# NXB-120：布局传输的身份保护

日期：2026-11-09。任务状态以 `tasks/backlog.json` 为准。

文件选择器返回或编辑器进程重建时，原有检查比较修订号与损坏文件指纹，但未明确比较布局所属身份。不同游戏、方向或摇杆模式的布局可能具有相同修订号和空指纹；单靠这两个值不能证明待恢复草稿仍属于当前配置。此前没有记录到用户数据被误写的实例。

客户端 390 为待处理导入、草稿导出与损坏备份导出保存原始布局身份，并在选择器返回、后台指纹读取结束和进程重建时，将身份与修订及指纹一并比较。身份不同或缺失时拒绝继续恢复；用户已保存的布局文件不被修改。身份来自原有游戏、方向、摇杆模式及控件选项的本机布局键，不会加入可分享的布局文件。

## 验证

- `LayoutIdentityTest` 使用生产身份与匹配逻辑验证相同身份成功，以及不同游戏、方向、摇杆模式、缺失身份、修订变化与损坏文件指纹变化均拒绝，即使两个不同布局修订都是零也不混淆。
- 1372 在游戏库编辑 BOTW 时启用草稿高对比度，进入系统导出选择器后终止后台客户端进程并返回：相同配置下显示“已恢复之前的草稿”，高对比度仍选中。再次进入选择器并终止进程，临时切换浮动摇杆设置后返回：编辑器显示未保存状态，高对比度未从旧草稿恢复。此测试证明该场景没有跨配置恢复，但不是所有游戏、方向或文件提供方的真机验证；独立单元测试覆盖身份比较。
- 测试前后 1372 的偏好文件逐字节一致，布局目录仍为空；未启动游戏或修改存档。两路服务保持空闲。两台 Pad 通过既有受管方式更新 390，安装 APK 的 SHA-256 与构建产物一致；1402 本轮没有重复选择器流程，应用数据和配对未清除。
- 固定 Moonlight Android 修订 `b48494cb96bff23d8886c4775cc4f39a1075495d`、NXBridge 389 源上离线 Gradle 构建成功；`adapters/input/moonlight-transfer-identity-390.patch` 独立重放后五个变更文件与构建源一致。

旧版本在选择器期间升级，或异常状态缺失身份时会拒绝恢复该待处理草稿；已保存布局不受影响。选择器进程销毁、备份导出竞争及不同 Android 设备仍需更广泛验证；这项保护不等于 Web / CLI / agent 管理 API 已实现。更新前安装包保存在本机忽略目录 `.nxbridge/controller-120/1372-before-390.apk` 和 `1402-before-390.apk`。
