# OoT 的 Metal 图形指令编码线程对照

2026-11-18 在 Mac mini（M4、16 GiB、macOS 26.5）上测试单实例。《时之笛》使用两台 Pad 日常入口的 S2Arm 修订 `d5435c3cf2a4bbdd0e36ed3cf21440ee714efa0b` 和完整离线游戏构建。目的是判断房间读档、出门入林时，独立 Metal 图形指令编码线程是否值得开启。

## 实验设置

- 1402 的存档备份逐文件通过已有 SHA-256 清单核对，每轮从同一备份重新复制。游戏及引擎目录使用日常只读沙箱。所有轮次共用同一引擎二进制和 Mach worker，独立使用存档、输入连接和缓存副本。
- 已部署的启动器过滤了 `DM_NVN_ENC_THREAD`。实验通过仓库启动器显式传递 `0` 或 `1`，保留已部署引擎的清单校验、存档锁、缓存锁和其他启动参数。引擎日志确认 Metal 4，开启组逐次记录独立编码线程启动。
- 游戏随附的 `pso_manifest.tsv` 为两行注释。第一组从同一标题画面缓存复制，预热时各编译 16 条管线。第二组先收集路线记录并在隔离实例预热，生成一份归档，之后每轮重新复制这份归档。各组内的后一轮均不继承前一轮新写入的游戏缓存。
- 按游戏源帧号向会话的本机输入桥发相同按键，50 ms 心跳维持手柄状态。从 worker 的 H.264 关键帧核对选档、房间、门口、森林和莎莉亚画面。视频按实际 bridge 模式输出，使用本机接收器；Pad、网络和实际显示延迟未取样。首次试跑因控制器心跳缺失止于选档，整轮排除。
- 表中统一统计引擎 `frames.tsv` 的第 1,970～4,500 帧，从确认读档至森林招呼，共 2,531 个呈现间隔。百分位取向上取整的秩，FPS 以间隔总数除以总时长计算。worker 的全会话源间隔有独立时间戳和统计窗口。

标题缓存关闭组的 3,320.9 ms 长帧同时记录了 326 个新管线、339 个着色器库和首次纹理上传。路线归档开启组在预热时命中 975 条、现编 0 条，其 1,076.9 ms 长帧记录提交加呈现 1,066.6 ms、GPU 16.1 ms，当帧新增管线、着色器库和纹理上传均为 0。邻近日志还有客体应用内存池上限返回；其因果关系未知。独立进程、相同文件缓存和交换执行顺序能减少干扰，驱动缓存、系统换页和其他进程负载仍会变化。

## 可重复的出门长帧

四次暖缓存测试在出门时都记录了同一批 175 次首次纹理上传，合计 94.2 MB，当帧新增管线和着色器库均为 0。关闭线程的两次整帧为 637.0 / 633.5 ms，上传计时为 495.2 / 461.0 ms。开启线程的两次整帧为 205.3 / 116.2 ms，上传计时为 130.4 / 45.9 ms。开启后这一帧重复缩短，四次仍均超过 100 ms。读档阶段还有另一批 700 次首次上传、352.3 MB，四次上传计时均为 126.5～145.3 ms。覆盖同一路段的最坏长帧没有随开关稳定下降，因此保留日常默认设置。

最后两轮还继续执行到约第 6,500 帧。关键帧显示关闭组完成下梯子、走到地面并出现对话框，开启组停在木平台。相同源帧号发送输入未保证动作落在相同剧情阶段，第 4,500 帧之后的数据排除出组间比较。原始记录仍含这一段。

另用相同路线归档和开启模式，在读档阶段独立采集 8 秒、5 ms 间隔的进程栈。样本中 `nx-83` 线程的 993 个观察里有 529 个落在 `h_nvnQueueSubmitCommands`，其中 367 个进入 `nvn_be_submit → xq_drain_ready`，其下包括绘制时的纹理解析与 `pkg_upload`。采样报告的进程物理占用为 8.7 G、峰值 9.0 G。本轮最长整帧 750.6 ms，提交加呈现仅 0.7 ms；未复现同样的 1,076.9 ms 提交停顿。进程栈覆盖整个窗口，不能将累计样本指派给前面某一帧。这轮有采样开销，排除出性能表。

下一步应在读档窗口按帧记录提交开始前的时间和 `xq_drain_ready` 内的等待，再与纹理上传及内存池返回值对齐。复测梯子到地面的路线时，要等到画面出现可操作平台再发送移动。六轮性能样本均正常退出，worker 编码失败为 0。启动器 20 项、缓存测试及 `make check` 通过。

## 新上游和部署

对固定的候选 `75852d41e1cc2f78a7c61195dcf4bb6d4543fd5d` 运行了它自己的 shader 链校验，现有游戏构建通过。对候选源码重放日常集成补丁时，文件缺少种子清单的处理已被上游实现，离屏呈现分支的上下文已变化；独立检查的内部预热补丁也在 Metal 后端和 tensor 路径上冲突。新版候选尚未构建或部署，运行锁仍为 `d5435c3`。[上游修订记录](NXB-140.md)

两台日常服务配置原先指定的 OoT 缓存根目录在检查时均缺失。已按原路径重建空目录，分别用已部署的启动器和沙箱通过 `--dry-run`。该检查未启动日常游戏。实验归档保存在独立缓存中，日常入口没有启用线程覆盖。

原始日志、输入时序、编码关键帧、逐帧数据和 `experiment.json` 位于本机 NXBridge 临时根目录的 `nxb129-enc-ab-20261118/`；测试缓存位于 NXBridge 缓存根目录的 `experiments/nxb129-enc-ab-20261118/`。本次结果仅适用于所列游戏、主机和场景。单次游玩速度、音画同步、Pad 手感与双开容量仍待各自验证。
