# NXB-135：持久数据、缓存与临时文件边界

日期：2026-11-11。

## 目标与变更

清理实验目录后，原日常入口依赖的引擎与游戏构建丢失，暴露实验目录兼作生产依赖的问题。[存储设计](../storage-lifecycle.md) 给出分类、使用边界、迁移与回退要求。S2Arm 增加可选 `DM_CACHE`，GameStream 目录校验检查该目录与其他可写目录是否重叠。未配置时沿用旧 `DM_TEMP/.s2arm-cache`，不自动搬迁或删除任何数据。

## 验证与限制

`tests/s2arm_launch_test.py` 验证独立缓存位置、符号链接与路径重叠拒绝、不同工作目录竞争同一缓存的写者锁，以及旧配置；`tests/s2arm_cache_test.py` 验证缓存身份与锁。GameStream `catalog::tests` 验证不同游戏目录冲突。`make check` 检查文档及任务数据。以上均为本机无游戏测试，不能证明已部署的引擎使用了新接口。

1402 当前只含 OoT 的临时服务仍使用原旧版启动器与实验路径；1372 配置及其他游戏缺失文件仍需恢复。本次没有迁移现有存档、缓存、游戏库或引擎，也没有停止服务或清理文件。ROM 资源存在单独的链接目标，迁移不能只复制游戏根。完整迁移和每款游戏实机验证属于后续工作，不能将设计或单元测试表述为完成部署。
