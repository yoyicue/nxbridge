# NXB-120：多指触点归属

2026-11-09。1372 上用 Android uinput 在离线输入工作台复现客户端 391 的问题：第一指按 ZL，第二指落在屏幕中部，松开第一指后，工作台仍显示 `ZL:255`，直到第二指松开。原视图接收了不在按钮区域内的第二触点，并把它作为按住的延续。这是本地工作台观察，未在真实游戏中复现。

客户端 393 只将落点在按钮范围内的手指记为该按钮的所有者。第一个所有者按下发出按下，最后一个所有者抬起发出释放；无关触点不延长按下。方向键采用单触点归属：主触点抬起时中和，其他已按住的手指不接管；工作台不将无关触点显示为摇杆或方向键的所有者。取消、切后台和编辑仍通过已有中和与屏蔽流程处理。

1372 的 393 离线工作台检查：ZL 按住、屏幕中部第二指按住、ZL 第一指松开时即显示中和；同一 ZL 内两指按住时第一指松开仍保持，最后一指松开后中和；方向键上方向的主触点松开后立即中和，外部第二指不显示为所有者。临时设备已退出。392 的同一输入实现另验证了 ZL 按住时切后台、返回后旧触点不复活、释放后新按正常；393 后续变更仅涉及摇杆和方向键的工作台观察记录。uinput 是模拟操作，不能证明真实握持或完整游戏输入链路。

`tests/ButtonTouchOwnersTest.java` 验证无关触点、同键不同释放顺序及取消的所有权转换。393 本机离线构建通过；独立 391 工作区重放补丁后，3 个修改文件与构建源码一致。两台经受管安装器更新，安装 APK 与构建产物哈希一致；1372 的 BOTW、1402 的 BOTW / TOTK 三份小手布局哈希均未改变。该轮工作台测试没有启动游戏或修改存档。此前 391 APK 分别在本机忽略目录 `.nxbridge/controller-120/1372-before-392.apk` 和 `.nxbridge/controller-120/1402-before-393.apk`。

仍需在真实游戏及真实手指下验证多指组合和方向键手感；未验收网络、实体手柄或端到端延迟。391 的原始工作台 XML 在本机 `.nxbridge/controller-120/multifinger-baseline-391/`，393 的 XML 与脚本在 `.nxbridge/controller-120/`。

## 真实游戏输入接口短测

随后在 1372 使用客户端 393、BOTW v1114112、离屏 nxnative / Mach 帧源及独立存档副本验证；测试帧源为游戏，不是工作台。视频出现后，先用 ADB 普通 ZL 按放检查链路，再用 Android uinput 模拟两指；主机游戏输入接口的变化轨迹依次观察到 ZL `256 → 0`（另一指仍在屏幕中部）、ZL `256 → 0`（同键两指，最后一指松开后归零）、方向上 `8192 → 0`（主触点松开、无关手指仍在）。同键两指中第一指松开后保持状态的检查和轨迹共同支持该次结果。记录在本机 `.nxbridge/controller-120/touch-owners-game-1372-20261109-144321/`。此处观察的是游戏输入接口，不等于游戏逻辑消费、游戏动作或物理屏幕端到端响应。

另保留两次未完整通过的尝试：第一次视频出现后直接注入的首个模拟 ZL 没有被采样，原因未确定；第二次先验证普通 ZL，两个 ZL 多指场景通过，但测试脚本错误地以 `1` 而非游戏接口上的 `8192` 判断方向上，故未完成方向键场景。第三次使用正确掩码完成全部三项。原始记录分别在本机 `.nxbridge/controller-120/touch-owners-game-1372-20261109-144158/` 和 `touch-owners-game-1372-20261109-144243/`。三次均使用各自的存档副本，结束后原存档哈希与启动前一致，临时会话与输入设备退出，原服务恢复空闲。真实手指握持、其他游戏、首次输入遗漏原因及长期稳定仍待验收。

## 首次模拟触点排查

针对上述一次首触点未采样，之后在 1372 的两次独立 BOTW 隔离启动中，等待出画并以 `dumpsys input` 确认临时 uinput 设备被 Android 框架识别，再依次注入两次 ZL 按放；两次会话各在游戏输入接口观察到 `256 → 0 → 256 → 0`。记录在本机 `.nxbridge/controller-120/first-touch-investigation-1372-20261109-144427/` 和 `first-touch-investigation-1372-20261109-144505/`。这两次是增加设备识别检查后的成功样本，不证明此前遗漏由设备注册引起；此前的失败尝试没有采集该状态，根因仍未知，也不能推及真实手指的首次输入。

第一次排查脚本将输入轨迹的索引错误地复用了存档校验变量，因此退出日志误报原存档发生变化；复核后当前原存档 20 个文件与两次排查前备份及上一轮备份逐项 SHA-256 一致，脚本变量已修正。两次均使用独立存档副本，临时设备及游戏进程退出，两路原服务空闲。

## 两台 Pad 的三键组合回归

两台 TALIH-PD2、Android 13、客户端 393 分别在 BOTW v1114112 离屏游戏会话中使用 Android uinput 模拟 ZL、方向上、X 的三指组合；各自先用普通 ZL 按放确认链路。游戏输入接口按顺序采得 `256 → 8448 → 8452 → 8196 → 4 → 0`，对应依次按住 ZL、加上、加 X，再依次松开 ZL、上和 X。结果证明该次输入接口采样保留组合和逐键释放，不代表游戏动作结果、真实手感或并发容量。每台单独使用存档副本和临时输入设备，原存档各 20 文件与备份 SHA-256 一致，服务及原配置恢复空闲。原始轨迹分别在 `.nxbridge/controller-120/input-combo-game-1372-20261109-144632/` 和 `input-combo-game-1402-botw-20261109-144725/`。

审查客户端同时发现，上游实体手柄按键按下不足 25 ms 时，释放处理会在 UI 线程等待剩余时间，原意是兼容短脉冲设备；本次没有修改这一兼容行为，也没有测量其对实际设备的影响。非阻塞替代应同时验证短按顺序、来源切换、后台中和和非 NXBridge 服务兼容性。
