# NXB-120：导出损坏布局备份

日期：2026-11-09。任务状态以 `tasks/backlog.json` 为准。

387 为游戏库离线布局编辑器增加“导出损坏备份”。恢复保存时原本保留在应用私有目录的备份可按当前游戏和方向列出，最新在前；玩家选择一项后通过系统文件选择器保存。界面明确提示文件未被修复，且可能包含游戏标识或其他隐私数据。该入口不修改当前布局或备份，不提供直接恢复损坏文件。

备份名限定在当前布局对应的文件前缀并拒绝跨目录或符号链接。选择前计算指纹，读取后再次比较，变化则拒绝写入内容；上限 8 MiB。文件选择器可能在写入前创建空文件，如果此后发生冲突或提供方错误，玩家选择的位置可能保留空文件或不完整文件，应用不会删除提供方中的文件。当前只在离线编辑器提供导出；串流中编辑不提供此入口。

## 验证

- 使用固定 Moonlight Android 修订 `b48494cb96bff23d8886c4775cc4f39a1075495d` 的既有 386 实验源构建 387，离线 Gradle `:app:assembleNonRootDebug` 通过。`adapters/input/moonlight-backup-export-387.patch` 在 386 副本上重放后，七个变更文件与构建源一致。
- `tests/LayoutRecoveryFilesTest.java` 使用实际备份组件验证原文件和备份一致、按布局身份列出、按字节导出、路径穿越拒绝、选择后备份变化拒绝、原文件变化拒绝和大小上限。`make check` 通过。
- 1372 的原布局目录为空。创建可识别的测试备份后，在 BOTW 的游戏库编辑器查看隐私提示、选择备份和使用 Android 系统文件选择器导出；导出文件与测试备份内容一致，备份未被修改。取消编辑后，仅清理本次测试的备份、导出和 UI 临时文件；没有启动游戏或修改存档。
- 两台 Pad 经既有受管安装方式更新到 387，已安装 APK 与构建产物 SHA-256 一致；升级前 386 安装包保存在本机忽略目录。1372 实测完整导出流程，1402 本轮只验证安装和哈希；配对及应用数据未清除。

尚未在实际损坏后生成的多份备份、第三方文档提供方、选择器期间进程销毁以及设备空间不足时完成设备验收；文件路径校验与指纹检查不能替代上述实测。原始损坏文件恢复、超过 8 MiB 的恢复，以及实体手柄和真实握持体验仍待独立处理。两路游戏服务未切换。
