# NXB-120：双游戏本地半包故障隔离

日期：2026-11-09。任务状态以 `tasks/backlog.json` 为准。

## 环境和边界

Mac M4、16 GiB、macOS 26.5；两台 Android 13 Pad 均为客户端 390，通过 Wi-Fi 分别连接独立的 NXBridge 服务。1402 启动 TOTK 1.2.1，1372 启动 BOTW 1.9.0；各自使用已部署的候选输入接收器、各自游戏进程和独立存档副本。为了隔离测试写入，另复制各自管线归档；1372 测试服务临时将 `DM_PSO_PREPARE` 从原配置的 `1` 改为 `0`，结束后恢复原启动脚本。两路均观察到客户端视频画面，但未采集游戏 FPS、音频隔离、玩家手感或户外场景。

## 操作与结果

两路启动前分别备份原存档并逐文件校验；测试均使用备份副本。TOTK 显示视频后启动 BOTW；BOTW 的 ZR 在游戏输入采样处保持约 20 秒。其间 TOTK 保持 ZL，通过仅属于 TOTK 会话的本地 TCP 代理发出半包并断开该连接。

- TOTK 从本机代理发出半包到游戏输入首次采样中立为 216.712 ms；服务端重新连接并先发中和帧。旧 ZL 未复活，松开后新的 ZL 按下与释放进入同一游戏进程。
- BOTW 的 ZR 在 TOTK 故障、重连以及新按放期间始终为 `512`，最后在自身触摸结束后归零。两路游戏采样和本机注入使用同一个 `CLOCK_MONOTONIC`；BOTW 按住后约 3.380 秒发生 TOTK 故障，BOTW 随后仍保持约 16.620 秒。TOTK 轨迹没有出现 BOTW 的 ZR 状态，BOTW 轨迹没有出现 TOTK 的 ZL 状态。
- 两个隔离实例退出后，两份原存档均与备份逐文件哈希一致；两路原服务恢复空闲。两路退出时服务日志均记录 `ControlStreamStopped`，不将其作为无故障退出证据。临时 TOTK 管线归档在检查两路空闲且没有打开文件后删除，原归档保留。

本次仅覆盖两款游戏启动 / 标题场景、两个触屏按键和一次本地 TCP 半包故障；不代表真实手持、实体手柄、Wi-Fi 断线、持续游玩、音画性能或并发容量通过。216.712 ms 不包含远端网络和物理屏幕，也不能证明 250 ms 端到端目标。

原始日志、两路输入轨迹与结果分别留在本机忽略目录 `.nxbridge/controller-120/dual-totk-20261109-141830`、`dual-botw-20261109-141859`；协调标记位于 `.nxbridge/controller-120/dual-fault-20261109`。不将游戏资源、存档或本机路径作为发行物。
