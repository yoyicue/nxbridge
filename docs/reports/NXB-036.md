# NXB-036：本机只读管理台

日期：2026-11-03。任务状态以 backlog 为准。

## 目标与范围

在正式单路管理依赖尚未完成时，先提供不依赖 Pad 的本机只读概览。服务只观察显式指定的本机 GameStream 服务，不管理会话、启动游戏、操作存档或改变配对。它为 NXB-038 提供 UI 和 API 原型，不改变 NXB-038 的前置条件或验收。

## 实现

- NXB-036 阶段的 nxbridge-host 固定监听本机回环地址，提供静态页面和 GET /api/v1/host。启动参数显式配置最多八个本机 IPv4 串流入口；无配置时显示空状态。后续 NXB-039 增加只读游戏库接口。
- API 对每个入口查询 GameStream 的 serverinfo，只转换已知空闲、忙碌、无响应和未知状态，不展示返回的任意 XML 或配对信息。已验证容量、托管会话数、游戏 FPS、串流 FPS 和操作延迟均为 null。
- 请求限制：16 个并发连接、8 KiB 请求头、800 ms 读取期限，入口响应最多 16 KiB 且受期限约束。拒绝非本机 Host、重复 Host 和非 GET 请求；服务不监听局域网接口。网页每五秒刷新，支持手动刷新，服务不可达时清除旧状态。
- 此阶段没有管理员账户、HTTPS、局域网访问、会话生命周期、存档锁或可执行的游戏库；不能用它取代正式 Host。

## 验证

cargo test --workspace --offline、make check-rust 和 node tests/dashboard_ui_test.cjs 通过；Rust 测试覆盖真实本机 HTTP 请求、服务端的空闲 / 忙碌 / 离线 / 错误响应、过大消息、慢客户端、慢后端、Host 校验和写请求拒绝。Node 使用轻量 DOM 夹具检查实际网页脚本对状态和错误的显示及标签按文本处理；不把夹具当作浏览器性能数据。

使用本机两路真实实验服务验证 API 均返回 ready；在 Safari 实际打开页面，看到两个“可连接”入口、未知容量和空性能指标，手动刷新后时间更新。两个入口空闲可响应不表示 Pad 在线、游戏通过验收或并发容量达标。

## 限制与交接

服务正在本机回环地址的 48200 端口运行；具体 PID、启动参数、日志与恢复脚本保存在忽略目录 .nxbridge/dashboard-036/。关闭浏览器不结束服务；重启前核实 PID 和启动时间。未连接 Pad，未触碰存档或既有 GameStream 服务。管理页面的登录、远程访问、真实游戏登记、会话操作和性能开销测量留待 NXB-038 及后续任务。
