# NXB-120：本地输入桥半包保护

日期：2026-11-09。任务状态以 `tasks/backlog.json` 为准。

## 修改

输入接收器此前对 22 字节本地 TCP 帧使用一个 1 秒完整帧超时。即使已经收到半包，剩余字节停住时旧的按键和轴状态也可能持续接近 1 秒。现在保留原有 1 秒空闲等待，避免与现有约 200 ms 心跳直接冲突；一旦收到不完整帧的首段，启动 200 ms 的单次截止时间，后续零散字节不能延长它。超时、断开或非法帧继续清空该连接的状态。令牌认证仍使用原有 1 秒等待。

200 ms 是针对本机进程间半包的候选参数，不是远端断网 watchdog，也不是 250 ms 端到端达标保证。正常完整帧不会进入半包等待；极端本机调度延迟仍可能导致误断，需要在真实游戏及负载下验证。完全静默且未收到半包的本地连接仍沿用 1 秒兜底。

## 验证与限制

- `tests/input_receiver_test.py` 共 20 项通过，新增检查：半包完成前不发布新状态；140 ms 后补齐的合法分片仍可用；半包停住后中和、旧尾部不能复活且新连接可重新输入；慢速追加字节不能延长截止时间；约 180 ms 心跳下的按住和释放正常。`tests/input_sender_test.py`、严格 C 语法检查和 `make check` 通过。
- 在本机接收器测试进程中，对已按住状态发送前 12 字节后停止，每 5 ms 轮询一次状态，旧实现 5 次观察为 940.68–945.64 ms，新实现 5 次为 202.32–210.86 ms。测量起点为本机 `sendall` 后，终点为测试进程首次采到中和；包含轮询和调度开销，不包括远端网络、真实游戏采样或画面。样本不用于声称产品时延达标。原始数据与实验记录在本机 `.nxbridge/controller-120/partial-frame-before.json`、`partial-frame-after.json` 和 `partial-guard-experiment.json`。
- 已从固定 nxnative 修订 `b8d16169c5fb7a3c6a936a950e294b1df4680551` 的现有实验工作副本创建独立副本，在其中编译 BOTW host；接收器源与本仓库版本哈希一致，编译成功。编译日志有 52 条图形代码警告，未将其视为本修改造成或已解决；该项编译检查本身没有运行游戏。

- 随后在 1372 平板通过隔离 BOTW 实例测试候选：正常显示游戏画面并在游戏输入采样处观测到 ZL 按住，持续约 3 秒后，测试代理向本机输入连接只发出 22 字节帧的前 12 字节。注入后首次游戏侧采样到全中立为 214.603 ms；该数值只有一次，时钟为同机 `CLOCK_MONOTONIC`，不包含远端输入或显示。测试代理先前因复用失败的 TCP socket 未连接到游戏，导致两次未观察到按键；修正后进行的这一次才是有效故障注入，不能将前两次归因为游戏输入故障。
- 游戏使用原存档备份的独立副本，原服务恢复为空闲后逐文件哈希对比原存档与备份一致。原始轨迹、代理状态、服务日志和试验记录保存在本机 `.nxbridge/controller-120/partial-game-20261109-133805`，不含在发布构建中。
- 在单独的本机 C 接收器进程中，同时启动两个各运行约 26 秒的 CPU 忙循环。按约 200 ms 周期发送 100 个合法分片帧，帧的按钮保持、轴值逐次变化：每次补齐之前采到上次完整状态，补齐之后均采到对应的新轴值；发送端测得的片间间隔为 11.61–146.33 ms。随后五个快速按钮状态采样为 `0 → 1 → 0 → 1 → 0`。
- 同一压力运行再进行五次半包停顿：本机发送半包到首次采样中立为 208.85–213.16 ms（约 5 ms 轮询）；延迟尾部均未恢复输入，每次建立新的本地认证连接后都能再次按下和释放。两个 CPU 进程分别使用约 25.99 秒 CPU 时间。以上是本地测试进程结果，采样时延包括轮询和调度，且不证明游戏输入桥在同一串流会话中自动重连，也不证明远端网络或极端负载下的表现。运行脚本为 `tests/input_receiver_stress.py`；逐次原始数据在本机 `.nxbridge/controller-120/partial-stress-faults-20261109.json`。
