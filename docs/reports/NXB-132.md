# NXB-132：时之笛双开压力归因与分辨率候选

日期：2026-11-10。任务状态以 backlog 为准。执行者：Codex。

## 范围与方法

分析 [NXB-131](NXB-131.md) 的双路与单路数据，并将上游直连后端的 `S2A_RES_SCALE=0.75` 作为诊断候选，在独立启动器、两份相同的存档副本和独立缓存下重复同一房间单路、双路静止场景。未修改 S2Arm 构建、日常目录或全局设置，不对游戏限帧。两次起始缓存都复制自同一新档缓存；各轮实际热身与系统背景不同。采集设置、硬件和构建身份沿用 NXB-131，帧表 `wall_us` 是宿主呈现间隔，不是客户端 FPS。每组约 60 秒，首尾有截图、期间每 5 秒采主机数据。

该候选使用本机忽略目录中的临时启动器向宿主显式传参；原生产启动器会过滤继承的 `S2A_` 变量。日志确认两路均接受 0.75 倍并缩小部分目标；但三张 2560×1440 上屏目标按上游策略未缩放，部分其他目标因着色器倍率信息不精确而退回原尺寸。两个 Pad 显示同一房间的截图，没有做逐像素、动态场景或长时间画质验收。

原倍率单路 / 双路 swap 已用范围分别为 5,378–5,394 / 11,845–12,158 MiB；0.75 候选分别为 5,642–5,658 / 11,308–11,425 MiB。系统 `vm_stat` 两个窗口首末样本间约 55 秒，原倍率单路 / 双路分别增加 swap-in 887 / 10,525、swap-out 0 / 27,668，压缩 64,423 / 287,412、解压 36,583 / 256,222；单位是系统页计数（本机页大小 16 KiB），包括所有应用，不能直接归给游戏。0.75 双路对应 swap-in 8,373、swap-out 10,584、压缩 116,402、解压 89,190；系统初始状态和后台活动不同，不能以一次数据宣称优化了换页。

每 5 秒 `ps %cpu` 的 12 次样本平均值，原倍率单路约 394%，双路两实例约 339% / 336%；0.75 候选单路约 396%，双路约 347% / 346%。100% 约等于一核，该口径是平滑瞬时读数，不是 CPU 利用率上限或精确核时。0.75 双路后引擎日志中两进程分别报告约 9,029 / 9,022 MB 物理足迹，读数不保证恰在采样窗口，可能包含共享页，不能相加；不支持宣称内存占用明显下降。

原倍率逐帧 GPU 时间字段有值的样本占 2,983/3,629、2,177/2,655、2,181/2,662 帧，分别对应单路 1402、双路 1402 / 1372；中位数为 13.67 / 18.35 / 18.27 ms。0.75 双路有值样本中位数为 18.24 / 18.33 ms。GPU 时间仅采用反馈有效且该帧完成的条目，缺失不可写 0；该数是单帧命令时间跨度，可能跨帧重叠，不等于整机 GPU 利用率。系统 swap / 压缩和 GPU 计时都在双开时升高；仅凭这一组顺序试验不能分离因果。

## 结论与限制

候选在该场景只带来约 0.5–0.6 FPS 的双路差异，远小于实验漂移可能造成的变化，不能认定有提速；未部署到日常服务。三张上屏目标未缩小及部分目标回退，限制了通过该参数降低图形负载的效果；不能据此推断所有场景。两轮没有交替重复，第二路启动时伴随加载和缓存工作，未测试动态游玩、游戏速度、端到端延迟和音画同步。此前 GPU 地址缺页未重现或修复。

下一步应优先按线程做低干扰 CPU / 提交路径归因，并在固定场景和背景下重复对照；同时研究游戏主体和图形资源占用。不要直接将外部 FPS 上限当作游戏时序修复。更多机型与多会话能力仍需独立验收。
