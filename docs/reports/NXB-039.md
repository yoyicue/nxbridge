# NXB-039：本机只读游戏库

日期：2026-11-03。任务状态以 backlog 为准。

## 目标与范围

在 NXB-036 的本机只读管理台增加游戏与构建元数据展示，不依赖 Pad，不启动游戏、不读写游戏资源或存档。它不替代 NXB-038 的游戏登记、启动或存档管理。

## 实现

Host 在启动时从显式指定的 TOML 文件读取版本化游戏列表。每款游戏有独立 ID、名称和多个构建；构建分别记录版本、登记状态、可选证据标识以及画面、声音、输入、存档、重连、体感和震动的状态。没有声明的能力默认为 unknown。允许的状态为 unknown、experimental、verified、unsupported；verified 必须填写证据标识，但本阶段并不自动核实该标识，页面明确显示为登记状态。

读取上限为 1 MiB，最多 64 款游戏、每款 16 个构建；拒绝重复 ID、无效状态、未知字段和超长输入。配置不接受运行路径、游戏文件或启动命令。空配置返回空列表；格式无效时启动失败，不静默加载部分数据。配置在启动时读取，修改后需重启管理台。

新增 GET /api/v1/games 和游戏库页面，两者共享同一份 Host 数据；页面仅展示登记内容。示例配置包含两个虚构游戏，不代表真实兼容性。本机忽略目录中另有用户 BOTW 1.9.0 实验构建记录，已按既有实验记录标为实验中；重连、体感和震动保持未知。

## 验证

cargo test --workspace --offline、make check-rust 和 node tests/dashboard_ui_test.cjs 通过。Rust 测试使用两个虚构游戏验证构建和能力隔离，覆盖空游戏库、重复和非法 ID、未识别字段、超大文件、无依据 verified 状态与真实 HTTP 查询。Node 夹具检查页面对游戏数据的显示、未知值和文本转义。

实际本机 API 返回两个真实串流入口和一款 BOTW 实验构建；Safari 实际显示版本 1.9.0、实验能力及未知项，游戏库导航有效。此结果不代表游戏的正式兼容验收或第二款真实游戏测试。

## 限制与交接

NXB-039 阶段管理台只绑定本机回环，尚未实现管理员身份、联网管理、游戏库写入、路径登记、启动、存档锁或生命周期。后续 NXB-041 增加本机元数据写入和已有目录绑定；正式产品入口及逐游戏验证继续按 NXB-038 和 NXB-081 执行。
