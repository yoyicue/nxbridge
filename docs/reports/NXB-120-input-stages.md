# NXB-120：输入主机阶段采样

日期：2026-11-09。任务状态以 `tasks/backlog.json` 为准。

## 环境与方法

Mac M4、16 GiB、macOS 26.5；1372 Pad 为 TALIH-PD2、Android 13、NXBridge Pad 363，经 Wi-Fi 连接。BOTW 构建 `v1114112`、nxnative 修订 `b8d16169c5fb7a3c6a936a950e294b1df4680551` 加本项目输入适配，离屏 nxnative / Mach 帧源；本次等待到客户端视频画面后采样，但没有截图确认具体游戏场景，不能声称是户外实战。串流配置沿用该实验客户端设置，本次没有独立记录其协商结果。1372 的 PSO 预热仅在测试服务中关闭，测试后恢复原启动配置。

隔离服务使用与当时部署版相同的输入解析与转发逻辑，并添加 `tests/fixtures/input-stage-instrumentation.patch`：记录认证控制消息中的 ZL 状态到达本机输入队列前的时间，以及转发 TCP 写入开始和完成时间。游戏引擎输入适配在 HID 输入状态写入结构体时记录取样时间。三处均使用 Mac 的 `CLOCK_MONOTONIC`；时间戳以纳秒记录但不表示纳秒级准确度。控制 UDP 经用户态代理转发、未注入故障；三个阶段都位于代理之后。`eprintln`、文件写入和代理均可能扰动调度，未测量其开销，结果不等同于无诊断部署的性能。

ADB 注入 20 次约 100 ms 的 ZL 触碰，依次等待游戏输入状态按下、释放后再进行下一次，每次间隔约 350 ms。使用 [分析程序](../../tests/input_stage_analysis.py) 将上一次游戏取样之后的首个对应状态到达，与该次游戏取样之前首个对应转发开始匹配；40 个边沿均匹配，且每个取样前只有一次匹配的对应到达。缺失或取样前出现反向边沿会被分析器报告为错误，而不是记成零时延。按放的注入节奏固定，样本不独立覆盖所有采样相位；每组仅 20 个样本，p95 为最近秩次，不能作为长期分位数结论。

## 本次结果

| 阶段 | 按下 p50 / p95 | 释放 p50 / p95 |
| --- | ---: | ---: |
| 认证输入到达队列前 → 本地 TCP 转发开始 | 0.019 / 0.028 ms | 0.0155 / 0.026 ms |
| 认证输入到达队列前 → 游戏 HID 输入结构取样 | 8.358 / 13.374 ms | 2.252 / 2.643 ms |

按下接收到取样范围为 2.001–14.816 ms，释放为 1.445–2.726 ms。这些数字包括诊断日志造成的未知扰动和排队；它们不包含手指触碰到 Pad 发送、无线传输、游戏逻辑消费、渲染、编码、解码或屏幕响应。按下与释放分布可能受固定注入节奏和取样相位影响，不能据此声称释放天然更快。也没有同条件关闭 UI 与启用 UI 的 A/B，因此 VC-13 尚未验收，固定一帧等待是否存在不能单凭此表判断。

本机忽略目录中保留 `timing-stagehost-server.log`、`timing-stagehost-game-input.txt`、`timing-stagehost-results.json` 和 `stagehost-analysis-checked.json`；输入轨迹属于操作行为，仅供本机诊断。两份日志可由上述分析程序和结果文件复核；诊断补丁仅供隔离构建，不默认启用或部署到日常服务。运行结束后原 1372 服务重启，空闲且无子进程；实验前后其存档 20 个文件 SHA-256 一致。原服务 PID 会变化，后续操作须重新核对。

分析器的匹配、缺失、反向边沿及时间顺序检查由 `python3 tests/input_stage_analysis_test.py` 验证；诊断补丁在当前工作区通过 `git apply --check`。后续仍需同条件的 UI 开销 A/B、客户端自身阶段和外部 input-to-photon 测量，以及真实手持与实体手柄验证。
