# NXB-120：双设备合成串流编辑与重连隔离

日期：2026-11-09。任务状态以 `tasks/backlog.json` 为准。

## 场景与结果

两台 Android 13 Pad 均运行客户端 383，分别连接 Mac 上独立的 GameStream 合成音画实例，协商为各自的 1280×720 / 30 fps / H.264。两路均使用自己的配对状态副本和独立端口；合成源不会启动游戏或写入游戏存档。服务日志记录的是协议侧完整按钮状态，不是游戏进程采样或触摸到画面的时延。

- 各路单独点击：1402 的面键在其服务出现 `1000 → 0000`，1372 无新增按钮；1372 的另一面键在其服务出现 `4000 → 0000`，1402 无新增按钮。
- 1372 进入串流内布局编辑并选择“试按”，点击面键没有产生该路服务按钮事件；同时 1402 面键仍产生 `1000 → 0000`。1372 取消编辑后，新面键产生 `4000 → 0000`，没有进入 1402。
- 1372 使用临时 Android `uinput` 保持一个面键，然后切到系统主屏：其服务记录 `1000 → 0000`，会话退出；此时 1402 仍可产生 `1000 → 0000`。1372 重新打开合成串流形成新会话后，仍保持的旧触点移动没有生成按键；释放旧触点并重新触碰后，新会话记录 `1000 → 0000`，1402 同时继续正常。

该检查覆盖明确退出、重开、编辑和模拟触点，不等于网络静默、半包、所有异常断线、物理手柄、不同游戏游玩或长期稳定性验收，也不证明两路并发性能达标。真实游戏标题界面的一次 Wi-Fi 故障记录另见 [双游戏试验](NXB-120-mixed-game-input.md)。

## 恢复与证据

原两路服务先确认空闲且无游戏子进程，再按 PID 和命令行核对后暂时切换；合成会话正常退出，原服务通过各自原启动脚本恢复，并均报告空闲。两台的游戏库已重新加载，测试未生成布局文件，未变更网络开关、游戏文件或存档。原始服务日志保存在本机 `.nxbridge/controller-120/dual-synthetic-383-1402.log`、`dual-synthetic-383-1372.log`，阶段结果为 `383-dual-editor-result.json` 和 `383-dual-reconnect-result.json`。设备仍为 383。

`make check` 通过；尚未完成的真实握持、物理手柄、网络故障及性能边界见 [NXB-120 交接](NXB-120.md)。
