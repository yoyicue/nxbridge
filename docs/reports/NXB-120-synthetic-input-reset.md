# NXB-120：合成源输入重置观测与双设备断网

日期：2026-11-09。任务状态以 `tasks/backlog.json` 为准。

## 实现

原合成会话只读取输入事件队列并记录 GameStream 按键标志，没有消费输入代次变化通知；静默或溢出时，即使实际游戏输入桥已发出重置，合成日志也可能继续保留旧状态，不能拿来证明中和。现在合成会话使用与游戏相同的 `game_input::forward`，连接仅绑定本机回环、随机端口和独立随机令牌的临时接收器，按完整按钮 / 四轴状态记录变化，并明确记录 `NXIR` 重置。观察对象是实际桥输出，仍不是游戏进程采样。合成日志会记录输入变化，不应混作无探针性能测量或公开玩家操作记录。

为兼容已有合成试验，日志继续提供按键的 GameStream 标志格式；现在该行只反映实际桥接受的控制器 0 和支持的按键，扳机与轴请看新的完整状态记录。合成观察器在会话结束时随会话任务关闭，不监听局域网。此改动只影响合成源，不改变真实游戏输入桥。

## 验证

- `cargo test --offline -p nxbridge-gamestream --bin nxbridge-gamestream` 共 11 项通过；新增测试通过实际桥验证按住后代次重置、旧代次和新代次仍按住时不复活、全中和后新按下生效。还验证旧日志按键映射。`make check` 通过。
- 两台客户端 383 分别连接独立的临时合成服务；服务使用此次修改的本机调试构建和各自配对状态副本，未启动游戏或改动存档。1372 按住面键后临时关闭 Wi-Fi，实际桥记录 `buttons=0x0001` 后 `NXIR` 中和 `buttons=0x0000, axes=[0,0,0,0]`；断网期间 1402 的独立会话仍记录 `1000 → 0000`。
- 1372 Wi-Fi 设置与连接已恢复，断线会话结束；重新打开合成会话后，两台的新按键均各自记录 `1000 → 0000`。重连启动阶段第一次尝试在 1372 未收到按键，首帧出现后再次尝试成功；由于没有同时记录客户端事件与首次点击时间，不能确定第一次未生效的具体原因，也不能将其计为成功。
- 该次中断没有精确记录断网生效与桥重置之间的同钟时间，不能证明 250 ms 目标；也不证明真实游戏采样、其他断线方式、实体手柄或长期弱网稳定性。此前带诊断扰动的游戏采样见 [输入失联时序实验](NXB-120-input-liveness.md)。

原始临时合成服务日志在本机 `.nxbridge/controller-120/dual-fault-383-1402.log`、`dual-fault-383-1372.log`，中断结果和首帧后重试分别为 `383-dual-network-result.json`、`383-dual-network-after-frame.json`。临时合成会话已退出，Wi-Fi 已恢复连接，两路原服务通过原启动脚本恢复并均为空闲；两台游戏库已刷新、测试没有创建布局文件。原服务仍运行原二进制，本次源码修改尚未部署为日常服务。
