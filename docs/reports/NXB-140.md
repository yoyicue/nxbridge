## 值得验证的变化

- S2Arm [1c1c20d](https://github.com/jhaizhou-ops/S2Arm/commit/1c1c20d0aa48218ad584a117cf19e9da5c82c0e1) 将 Mac Metal 4 的独立编码线程改为默认开启。上游报告一款 Switch 2 游戏固定场景中关闭约 30–32 FPS、开启约 60 FPS；另一款 30 FPS 游戏的样本因负载超过上游阈值仅作参考。**不是 NXBridge / OoT 的实测，不能外推性能。**本机 M4 报告支持 Metal 4；当前锁定的 `d5435c3` 源码已有该开关，1402 / 1372 OoT 配置均未设置 `DM_NVN_ENC_THREAD`，因此值得先在隔离存档以相同二进制、同一路线作 0 / 1 对照。实际后端和日志须核实，不据显卡能力推断游戏一定采用 Metal 4。
- S2Arm [a3d30b4](https://github.com/jhaizhou-ops/S2Arm/commit/a3d30b4a5045a0c8dbd24683dbdbeb417cf7e0de) 优化线性纹理脏行上传，但变更位于 `graphics/nvn/replay/`。上一轮 NXBridge Mac 构建未包含该回放层对象，不能直接当作当前 OoT 的优化；需先核对新构建对象和路径。上游还修改了 [SDK 交换间隔行为](https://github.com/jhaizhou-ops/S2Arm/commit/e78782b1788567b6d070ee6c50cb890ce3201f74)，其对时序 / 限帧的作用需要独立验证。
- nxnative [1467219](https://github.com/seedds/nxnative/commit/1467219) 增加手柄陀螺仪数据资格判断，减少虚报体感数据抢占其他来源；[aca80c3](https://github.com/seedds/nxnative/commit/aca80c3) 增加本机 DualShock 4 蓝牙体感读取。它们作用于引擎本机手柄路径，**不会自动打通 Android → GameStream → NXBridge → 游戏的体感输入**。上游还修改管线需求持久化等图形流程；旧的 Metal / SDK 阻碍及适配差异仍需重新核实。
- NX2Apple 的 rc6 包含多引擎入口和 S2Arm 外部构建相关工作，仍是候选版本。其构建器 / 打包能力值得评估；不能认为已满足 NXBridge 的独立会话、存档隔离或游戏运行要求。
- Sunshine [207a4b6](https://github.com/SunshineStream/Sunshine/commit/207a4b6d3d7c8eb562f0169b9788b1732aa32c20) 增加原生 VideoToolbox 编码路径；[43b7450](https://github.com/SunshineStream/Sunshine/commit/43b74505bc938e2a044d83b11a1ce13199a75753) 增加编码分辨率上限。可用于研究 / 对照，但本项目 Rust GameStream 当前没有因此获得能力。
- Moonshine 新增按连接执行并设置时限的 TLS 握手、视频码率控制调整等，需与本地派生核心逐项对照；项目音频已有自己的时间戳 / FEC 改动，不能直接把上游音频修复当作未实现或自动覆盖现有逻辑。
