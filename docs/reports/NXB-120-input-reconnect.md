# NXB-120：游戏会话中的本地输入桥重连

日期：2026-11-09。任务状态以 `tasks/backlog.json` 为准。

## 修改

本地输入 TCP 连接断开或写入超时时，旧的转发任务直接退出；游戏会话管理器检测到输入任务结束后会停止该游戏会话。现有游戏转发路径会在当前会话内尝试重连：清空断开期间排队的输入，在新连接先发送 `NXIR` 中和帧，并等待重新连接后收到的全按钮、四轴中立状态，才接收新的按住或轴移动。每条新连接重新认证，序号从该连接重新开始。重试使用 200 ms 间隔、5 秒恢复预算；反复建立后立即关闭的连接不能无限重置预算，连接稳定约 1 秒后才允许新的预算。输入会话结束时不等待恢复预算，正常清理并退出。

安全取舍：如果玩家在连接断开期间已经松开，而中立事件在新连接建立前被丢弃，第一次新按可能会被屏蔽；松开再按才能恢复。接收端当前协议没有应用层确认，TCP 写入成功不证明游戏逻辑已消费输入。合成音画观察器目前仍使用单连接版本，不代表它已覆盖游戏路径的自动重连。远端断网检测、服务端到客户端的提示以及同屏实体手柄行为仍需单独验证。

## 验证

- Rust 测试覆盖：断线期间旧按下 / 中立 / 按下队列不重放；重连后持续按住保持中立，新的中立和按下恢复；反复接受后关闭连接最终耗尽恢复预算；输入会话关闭时不等待重连超时。`cargo test --offline -p nxbridge-gamestream` 共 14 项通过，`rustfmt --check`、接收器 20 项测试、发送器测试及 `make check` 通过。
- 1372 在独立 BOTW 1.9.0 运行实例、独立存档副本与本地代理下测试。维持 ZL 按住时代理仅转发输入帧前半段，并在接收器超时后断开该本地连接。游戏采样归零后，服务端自动重新连接并先发送 `NXIR`；旧 ZL 按住没有复活，玩家模拟松开后，新 ZL 按下和释放在同一个游戏进程的输入采样中出现。调试服务和单独构建的 Release 服务各测试一次；半包发送到首次游戏输入采样中立分别为 211.034 ms、218.405 ms，均为单次本机诊断，并非远端 input-to-photon 或长期性能结论。
- 隔离测试前为原存档建立备份，测试使用备份副本；测试后原存档与备份逐文件哈希一致，临时游戏及 worker 已退出。原始代理状态、游戏输入轨迹和服务日志分别留在本机忽略目录 `.nxbridge/controller-120/reconnect-game-20261109-140323` 与 `reconnect-release-20261109-140503`。两次结束游戏后服务记录 `ControlStreamStopped`，不能将其记为无故障退出证据。

## 部署与恢复

两台实验服务在确认无会话和子进程后切换至经过上述隔离测试的 Release 服务端，部署文件哈希与测试构建一致。1402 的 48989 与 1372 的 49989 当前均处于空闲。服务端重连协议依赖已部署的 `NXIR` 接收器。随后两台 BOTW 入口也切换到 200 ms 半包候选引擎，并分别做隔离存档烟雾测试；详情见 [半包保护记录](NXB-120-partial-frame.md)。后续 1402 的 TOTK 已单独进行半包故障注入并更换候选引擎，详见 [TOTK 输入记录](NXB-120-totk-partial.md)；不能将单会话结果外推为并发能力。

旧服务二进制及新二进制备份在 `.nxbridge/controller-120/reconnect-deploy-20261109-140608`，两路启动脚本和存档未修改。如需回滚，先确认两路没有玩家和 worker，再运行 `python3 .nxbridge/controller-120/rollback-reconnect.py`；脚本再次核验 PID、命令、会话及端口后才切换，并保留回滚前二进制。长期运行、多次真实断线、不同游戏及实际物理手柄仍待验收。
