# NXB-120：输入组合快照与日常诊断轨迹

日期：2026-11-09。任务状态以 `tasks/backlog.json` 为准。

## 组合与中和回归

接收器按钮边沿保留四轴快照，轴单独变化不排队；游戏每次请求取样时依序消费一个边沿。`tests/input_receiver_test.py` 新增两项基于实际 C 接收器和 TCP 协议的测试：

- 多个按钮组合和四轴变化在游戏取样前连续到达时，按边沿顺序取出各自完整快照；队列排空后使用最近的纯轴变化。
- 边沿队列溢出后，按钮已释放但任何轴仍偏离零都不能解除中和隔离；全按钮和四轴归零后，新的按键和轴才可进入。

接收器 16 项及发送器 1 项通过。这覆盖受控输入快照，不证明真实游戏对短按的逻辑消费、实体手柄、多点握持或所有并发时序；接收器和引擎运行代码本次没有更改。

## 日常轨迹改为显式开启

`nxbridge_input_trace` 是用于诊断的可选同步文件写入：在输入状态改变时记录，包含操作行为，并可能扰动游戏线程。1402 日常服务此前未设置 `NXBRIDGE_INPUT_TRACE`；1372 的本机实验启动脚本此前固定启用。现在从 `.nxbridge/botw-card/second-pad/start.py` 移除该默认值，先确认服务空闲且无子进程，再按精确 PID 重启；新进程环境确认没有该变量，两路服务均空闲。原启动脚本备份在本机忽略目录 `.nxbridge/controller-120/second-pad-start-before-trace-opt-in.py`；原有轨迹文件未删除。

需要诊断时，可在确认该服务无会话和子进程、按 PID 安全停止后，显式设置 `NXBRIDGE_INPUT_TRACE` 为本机受保护的日志文件路径，再运行启动脚本；这会重新启用同步诊断写入。是否支持带单调时间戳的格式取决于实际引擎构建，不能由源代码配置推断当前部署引擎已包含该能力。恢复默认只需在不设置此环境变量的情况下启动。

本次没有运行真实游戏或采集性能对照，不声称帧率、延迟或卡顿改善；真实握持、实体手柄和游戏动作仍待单独验收。`make check`、接收器和发送器测试通过。
