# NXB-107：音频源时钟与有界间断恢复

日期：2026-11-04；2026-11-05 补充调度诊断与修复。任务状态以 backlog 为准。

## 目标与范围

单台 Pad 的真实 BOTW 链路出现 worker 本地发送失败和客户端音频积压。用户确认此前操作均为测试，授权切换服务；每次切换前先结束对应会话、确认游戏和 worker 退出并备份隔离存档。测试使用已登录 macOS 用户会话内的 nxnative 离屏输出、Rust GameStream 和 NXBridge Pad；不是性能或多设备验收。

## 最终变更

游戏与合成音频通道携带会话 ID、运行代次、主机单调时钟纳秒 PTS、间断标志和 PCM。协议核心拒绝旧会话、重复和倒序数据；空队列下，已声明的小缺口最多补四个 5 ms 静音块，较大缺口重锚。有积压时丢弃过旧的音频并重锚，不用补静音继续扩大积压。11 月 5 日将唯一的 5 ms 输出节拍移入编码线程，编码前淘汰在该级排队超过 20 ms 的 PCM，并最多保留四块；网络发送端每次只允许一个数据 / FEC 批次等待完成，停止会话可取消等待。RTP 时间戳仍每包递增 5 ms，以维持客户端 FEC 分组。队列满时丢弃并向下一次成功提交的块标记间断。

worker 与 Rust 之间的私有 Unix 数据报发送和接收缓冲均设为 32 KiB；本机约可容纳 16 个 5 ms 数据报。各级队列分别有界，缓冲容量不等于端到端延迟保证。实验 worker 增加发送失败分类，区分缓冲满与其他错误。更改位于 `crates/nxbridge-gamestream`、`tests/nxnative_mach_worker.m` 及固定修订的 `vendor/moonshine-core`，其来源和本地修改见 `NXBRIDGE-NOTICE.md`。

## 结论与限制

新版本已在真实 Pad 和游戏链路测试，但 worker 仍有丢块，客户端部分日志仍提示积压；音频可靠性和完整单台验收未通过。静音填补不恢复原始声音；重锚可能产生跳变。混合场景的运行时间不构成连续实际游玩稳定性验收。尚未完成音画同步、端到端延迟、正式帧率与断线标准，也不能推断多设备容量。

## 2026-11-05：可复现的调度问题与修复

用户授权诊断并修复。工作前对涉及的源码和文档保存快照，沿用当前任务，没有覆盖其他 agent 的改动。检查时实验入口为空闲且没有游戏 / worker 进程；ADB 没有在线设备。本次本机探针不启动游戏，不使用玩家存档，也不代表 Pad 验收。

### 诊断与对照

原音频桥在编码前节拍输出，但后方仍有 16 个 PCM 帧和 10 个网络包的独立缓冲。暂停下游包消费后，积压可以越过前面的节拍控制。使用真实 Opus / FEC、相同 5 秒 48 kHz 双声道源，在第 100 个数据包后暂停消费 100 ms，结果如下。这里的观测点是编码到网络发送的交接处，不是 Pad 或物理网卡。

| 探针 | 原实现 | 修复后 |
| --- | --- | --- |
| 无停顿，产生 1,000 个 5 ms 音频块 | 输出 1,000 个数据包 | 输出 1,000 个数据包 |
| 无停顿，任意 5 ms 窗口最多数据包数 | 2 | 2 |
| 注入 100 ms 停顿，任意 5 ms 窗口最多数据包数 | 21 | 2 |
| 注入停顿后的总数据包数 | 1,000 | 982 |

修复后停顿场景少输出的 18 块是过期 PCM 的丢弃；不声称恢复了这些声音，也不声称停顿期间无声音缺口。发送完成握手防止积压提前编码，旧 PCM 在分配网络序号前淘汰，所以发送的 RTP 序号、5 ms 时间步与 FEC 分组仍连续。该级 20 ms 上限不是端到端延迟保证。

第二个问题是视频 FEC 缓存构造与分包直接占用异步 I/O 线程。以一个未命中过缓存的 200,000 字节视频帧、实际 Unix 数据报 socket pair、32 KiB 缓冲和每 5 ms 一个 1,936 字节音频数据报进行对照：

| 单 I/O 线程压力探针 | 同步分包 | 计算移至 blocking worker |
| --- | --- | --- |
| 产生 / 收到音频数据报 | 300 / 235 | 300 / 300 |
| 本地 socket 缓冲满 | 65 | 0 |
| 最大接收间隔 | 407.002 ms | 9.752 ms |
| 冷视频计算及调度耗时 | 405.638 ms | 396.066 ms |

此对照刻意只使用一个异步 I/O 线程，证明同步计算阻塞收包的机制；生产服务使用多线程运行时，不能把这些数值直接当成真实游戏改善幅度。修复将视频预热与逐帧分包各自放入等待完成的 blocking job，每路同时最多一个，保留原有缓存、加密状态、序号和有界队列。不改 FEC 算法，不将网络侧修复说成游戏 shader 卡顿已解决。

`game.rs` 每十秒记录源 PTS 到 Rust 的最大年龄、接收最大间隔及超过 20 ms 的累计块数；编码线程记录编码最大耗时、等待发送完成的最大耗时、编码入口最大队列年龄和过期块数。源与 Rust 使用同机 `CLOCK_MONOTONIC`，没有跨设备时间相减。
