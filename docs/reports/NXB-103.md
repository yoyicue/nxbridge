# NXB-103：macOS CI 与基础检查

日期：2026-11-03。执行者：Codex。

## 目标与范围

为公开前工程提供 macOS 无设备自动构建、测试、格式与基础静态检查；不改变游戏进程和已有设备。

## 最终变更

新增 `.github/workflows/ci.yml`，对 push、pull request 和手动触发运行 macOS 15 任务；只授予 contents 读取权限，不保留 checkout 凭据，第三方 Actions 固定到提交，Rust 固定 1.97.0，Cargo 构建和测试使用锁文件。工作流检查项目、发布候选内容、测试、NXBridge 自有 crate 格式、Clippy、合成音画和无设备原生媒体。Clippy 的既有警告不视为错误；后续逐项清理后再考虑升级为严格门禁。vendor 不被自有格式检查重排。

## 验证证据

- `go run github.com/rhysd/actionlint/cmd/actionlint@v1.7.7 .github/workflows/ci.yml`：通过；YAML 亦经本机 PyYAML 解析。
- `cargo fmt -p nxbridge-host -p nxbridge-media -p nxbridge-stream -p nxbridge-gamestream -- --check`：通过。
- `cargo test --locked --workspace --offline`：24 项测试通过。
- `cargo clippy --locked --workspace --all-targets --offline --no-deps`：退出 0，存在既有警告，未设置 warnings-as-errors。
- `make check-native-media`、`NXB_CARGO_OFFLINE=1 make check-synthetic`、`make check-release-content` 通过。
- `cargo fmt --all -- --check` 不通过，原因是 vendored 上游文件格式；没有对第三方代码执行批量重排。

## 结论与限制

当前仓库尚无首次提交和 GitHub 远端，此工作流未在 GitHub Actions 托管运行器实际运行；macOS 15 原生框架、Homebrew 依赖安装与托管 runner 的实际行为仍待首次 CI 验证。CI 不覆盖真实游戏、GPU 硬件串流、Moonlight 设备、游戏性能、许可合法性或全新系统安装。当时完整发布检查因未选择根许可证而阻断；之后用户已选择 MIT，见 [NXB-104](NXB-104.md)。

## 恢复与交接

没有修改运行中的服务或设备；actionlint 通过 Go 运行并下载到本机工具缓存。首次提交并配置远端后检查工作流实际运行结果。
