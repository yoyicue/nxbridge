## 测试结果

- 1402 使用 TOTK 1.2.1、独立存档副本、临时游戏库配置和本地输入代理。第一次启动的客户端在等待首视频时超时；日志记录管线归档打开约 6.3 秒，游戏随后产生视频帧，但不能仅凭此断定超时原因。游戏退出，原服务恢复空闲，原存档与备份逐文件哈希一致。该次没有进行输入故障注入，不算通过。
- 第二次隔离启动出现视频并观察到 ZL 按住；代理发出本地半包后，游戏首次采样中立为 218.169 ms。输入桥在同一游戏进程重连并发送中和帧，旧按住未复活，松开后新的 ZL 按下和释放均到达游戏输入采样。原存档与备份逐文件哈希一致。这是一次标题场景和本机故障注入，不是远端网络、物理屏幕时延、实际游玩或长期稳定性验收。
- 随后 1402 空闲时，将游戏库 TOTK 入口切换到独立候选引擎；BOTW 条目逐字段与切换前一致。基于部署配置再用存档副本启动 TOTK，观察到视频和 ZL 按下 / 释放；测试结束后原服务恢复空闲，原 TOTK 存档仍与备份一致。该次部署后烟雾测试没有再次注入故障。1372 及 BOTW 配置没有切换。
- 原始记录保存在本机忽略目录 `.nxbridge/controller-120/totk-partial-20261109-141329`、`totk-partial-20261109-141414` 和 `totk-deployed-smoke-20261109-141532`；临时管线归档副本在游戏和 worker 退出、两路空闲后删除，原管线归档保留。游戏资源与存档不进入仓库。

1402 的 TOTK 与两台 BOTW 均使用各自含 200 ms 本地半包保护的实验引擎，服务端使用已验证的本地重连逻辑。此超时不等于远端失联到中立的 250 ms 验收，首次视频超时仍需处理；TOTK 的实际游玩、声音、存档往返、真实手柄、长期稳定和混合并发均未由本次验证。
