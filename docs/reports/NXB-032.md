# NXB-032：Rust GameStream 合成音画原型

日期：2026-11-02。已完成合成音画原型验收；正式游戏离屏输出和生产服务仍待后续任务。

## 目标与范围

以 NXB-031 的同一媒体契约产出带帧号的运动图与同步提示音，通过 Rust GameStream 服务端发送给真实 Moonlight，并验证输入、断线与重连。实验不接管正在运行的游戏或 Sunshine，也不改动游戏存档。

## 已实现与验证

- `nxbridge-stream::synthetic` 生成 BGRA 测试帧、可见六位帧号、运动方块、每秒 100 ms 的白色提示和同步 880 Hz 双声道 PCM。帧与 PCM 的描述符使用相同 epoch、统一纳秒时钟、媒体缓冲和租约模型；见 [媒体接口 v1](../media-abi-v1.md)。当前为离线、内存生成，还不是实时媒体服务。
- `synthetic-fixture` 写出 60 帧 320×180 BGRA 和两秒 48 kHz PCM；将它们交给本机 `ffmpeg` 的 `h264_videotoolbox` 与 `libopus` 生成 `.nxbridge/synthetic-032/synthetic.mkv`。`ffprobe` 实测 H.264、320×180、30 fps、Opus 48 kHz 立体声，文件时长 2.008 秒；截图 `.nxbridge/synthetic-032/frame-30.png` 可见帧号与运动图。这是本机文件编码，不是 Rust 的 VideoToolbox 绑定，也不是 Moonlight 播放或端到端同步验收。
- 增加有界 Annex-B 访问单元切分器，按访问单元分隔符处理任意读取边界并识别 IDR；它要求编码器逐帧插入 AUD，不是通用 H.264 解码器。将同一合成视频通过 `h264_videotoolbox` 和 `h264_metadata=aud=insert` 写成 Annex-B 后，`annexb-inspect` 实测 60 个访问单元、2 个 IDR；目前仍是离线文件，尚未接入协议包发送或客户端的关键帧请求。
- `cargo test --workspace --offline` 中媒体契约与合成源测试通过；`make check` 与 `make check-rust` 通过。源码和 ABI 测试证明数据结构与有限队列模型，不证明操作系统跨进程句柄、GPU 完成通知或编码回调。

## 协议研究与隔离探针

- ADR-0002 指定的 [Moonshine 修订 79554f8](https://github.com/hgaiser/moonshine/tree/79554f853135cbac44502b58093a4eb0f0f5e6f1) 是 BSD-2-Clause；其协议核心同时耦合 Linux 的 Wayland/DRM、Vulkan、PulseAudio、输入及 systemd。未把整套 Linux 栈接入本项目。
- 另观察 [rgsp-cast 修订 2eeb0fa](https://github.com/codebutler/rgsp-cast/tree/2eeb0fa63221a9e72dfc51ea77a01a3be8ff0e1e) 的 `vendor/moonshine/moonshine-core`：项目说明将其标识为基于 Moonshine v0.15.0 的裁剪版，暴露已编码帧、PCM 和输入桥。与 ADR 固定的上游 v0.16.1 修订不同，不能当作同一版本。根项目使用 GPL-3.0，其 vendored 子树保留 Moonshine BSD-2-Clause 许可证，但子树后续改动的授权范围仍需核查；当前未复制或引入为 NXBridge 生产依赖。
- 该候选核心 `cargo check -p moonshine-core` 在本机成功。额外在忽略目录创建 Rust loopback 探针，修改候选副本以显式将状态放入 `.nxbridge/synthetic-032/probe-state/`，关闭配对、仅监听 `127.0.0.1` 的 48989 / 48984 / 49010，避免碰现有服务。Rust 探针编译成功，直接 HTTP 客户端请求 `127.0.0.1:48989/serverinfo` 返回 200、正确主机名和 HTTPS 端口。它只证明启动与一个 HTTP 响应，不证明 TLS 配对、RTSP 或媒体；探针已停止。普通 Python `urllib` 的初次请求受环境代理影响未成功，使用直连 `http.client` 得到上述结果。
- 上述副本位于 `.nxbridge/rgsp-cast-research/`，探针在 `.nxbridge/synthetic-032/protocol-probe/`。这两处是本机忽略的研究工件，不是可发布依赖；本地改动可通过 `git -C .nxbridge/rgsp-cast-research diff` 检查。探针目录中的证书和状态为本机实验数据，不进入版本库。

## 2026-11-02 真实客户端验收

- 实现 `crates/nxbridge-gamestream/`：通过共享媒体 ABI 生成 BGRA 与 PCM，Rust 协议核心接收由 FFmpeg `h264_videotoolbox` 编码的 H.264 和经转换的 5 ms PCM，再由协议核心 Opus 编码、分包和发送。编码器进程是 FFmpeg，尚不是 Rust 直接调用 VideoToolbox 的绑定。协议副本的来源、两份许可证及本地修改见 `vendor/moonshine-core/NXBRIDGE-NOTICE.md`。因修改的子树授权不够明确，此实验实现保守按 GPL-3.0-only 管理；不把其视为原定 BSD 上游同一修订。
- Pad 上的真实 Moonlight 经手动添加测试端口与独立证书配对，协商 1280×720、30 FPS、H.264 5 Mbps、48 kHz 立体声。截图 `.nxbridge/synthetic-032/pad-live.png` 和 `pad-live-b.png` 显示不同帧号与移动方块；客户端实际使用 `c2.mtk.avc.decoder`。Sunshine 没有参与该测试会话。
- 第一次连接中 Moonlight 音频 FEC 的时间戳断言失败并崩溃；定位为候选核心以墙钟近似生成 RTP 时间戳。修正为每个成功发送的 5 ms 包递增 5 后，后续真实客户端持续接收音视频。RTSP 协商实测控制 V2 加密、音频加密、视频不加密，视频 FEC 20%；这是所测模式，不代表视频加密已验证。
- 临时独立调试客户端在音频解码后检查 PCM：每秒出现一次非零提示音。为验证扬声器路径，临时将媒体音量从 0 调至 5/15，平板麦克风 8 秒中检测到 107/791 个 10 ms 窗口含 880 Hz 成分；音量已恢复为 0。探针仅记录统计值，不保存麦克风音频。
- 初次采样中客户端音频处理早于对应视频提交约 170–180 ms。对该 720p/30fps 实验增加固定 180 ms 发送补偿后，同一客户端单调时钟下，音频解码与视频提交的最近十个样本差值为 +4.34 至 +14.80 ms。它不包含屏幕呈现与扬声器的实际硬件延迟，不能作为物理音画同步或其他分辨率的结论。
- Moonlight 调试版内置 FEC 验证在收到分片后模拟丢弃一个视频数据分片，用服务端的冗余分片恢复并逐字节校验；实测多帧恢复一致。客户端发送 IDR 请求，服务端发送关键帧；当前编码器以每 30 帧周期 IDR 响应，尚不支持逐请求立即强制 IDR。
- 平板触屏 A 按下 / 释放分别收到 `0x1000` / `0x0000`。按住时强制结束客户端，服务端超时结束旧代次并丢弃输入状态；重新连接使用新代次、从帧 1 的 IDR 重新开始，不重放旧按键，新的 A 按下 / 释放正常。截图 `.nxbridge/synthetic-032/pad-reconnected.png` 记录重连。
- `cargo test --workspace --offline`：10 项通过；`make check`、`make check-rust` 通过。过滤过的客户端媒体事件在 `.nxbridge/synthetic-032/client-events-final.log`；该目录忽略且包含本机实验状态，不能提交。结果不代表游戏、多实例、长期网络稳定性或端到端延迟。

## 运行与恢复

准备本机 Rust、FFmpeg（含 `h264_videotoolbox`）及 Opus；首次构建需获取 `Cargo.lock` 锁定依赖。以 `cargo run --locked -p nxbridge-gamestream -- BIND_IPV4 STATE_DIR 48989` 启动，绑定具体本机 IPv4，`STATE_DIR` 为专用私有目录。平板手动添加 `BIND_IPV4:48989`，配对时将平板显示的四位 PIN 写入该目录的 `pair-pin`；服务只在恰有一个待配对客户端时读取并删除该文件。测试客户端必须选择 H.264、720p、30 FPS、立体声。端口组为基准 HTTP 端口及其相对偏移；不要与现有服务冲突。`Ctrl-C` 停止实验主机。

实验主机及临时测试客户端已停止，临时客户端已卸载；原 Moonlight 实验版保留且恢复 Sunshine Desktop 串流、60 FPS；平板原搜狗输入法及音量 0 已恢复，ADB reverse 为空。Sunshine PID 38938 与游戏 PID 58485 仍在运行。实验文件和测试证书留在 `.nxbridge/synthetic-032/`；清理前确认无需复查。NXB-035 仍等待 NXB-010。
