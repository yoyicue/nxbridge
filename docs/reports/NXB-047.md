# NXB-047：通过 Sunshine 原生手柄协议接入游戏会话

日期：2026-11-02。状态：单会话原型已完成；性能与多会话验收仍待后续任务。执行者：codex。

## 目标与范围

按用户要求，平板的触屏输入使用 Moonlight / Sunshine 原有的 GameStream 手柄包，不使用独立的局域网输入协议。Sunshine 已认证的客户端输入会话在主机本机转交给一个目标游戏进程；不经过全局键鼠、焦点或付费虚拟手柄驱动。

## 最终变更

- Sunshine `63d35f702ee9e362e43263742981836ec0710384`、Moonlight Android `b48494cb96bff23d8886c4775cc4f39a1075495d` 和 nxnative 引擎 `b8d16169c5fb7a3c6a936a950e294b1df4680551` 均使用独立固定修订副本；没有覆盖原有 Sunshine 或用户 NX2Apple 工作副本。
- Sunshine 接收已配对客户端的 `NV_MULTI_CONTROLLER_PACKET` 后，匹配其认证证书与本机预配置的指定客户端证书；仅将目标会话的 0 号手柄转换并写入本机游戏监听器。网络输入沿用 Sunshine/Moonlight 协议；本机 Sunshine 与游戏之间使用既有回环连接。其他未匹配的输入会话不送入这个游戏进程。
- 按钮变化按顺序发送，发送队列有界；ZL / ZR 阈值变化不会被 Sunshine 的原手柄包合并吞掉。游戏进程在本机连接 EOF / 超时时中和；Sunshine 输入会话断开时停止发送器并关闭连接。断开后恢复串流时从中和状态开始。当前只验证单 worker / 单控制器，不代表多会话隔离已验收。
- 独立客户端包 versionCode 318 保留 Switch 标记触屏布局；`VirtualController.java` 与固定 Moonlight 原版一致，通过原有的 `ControllerHandler.reportOscState` 发送。使用 `xpad2 install apk` 升级；原版 Moonlight 和现有配对保留。
- 源码位于 `adapters/input/sunshine_bridge.hpp`、`apply_sunshine.py` 和 `apply_native_client.py`。三个临时干净 worktree 依次应用适配后，10 个目标文件与本次构建逐字节一致。
- Sunshine 独立构建使用固定上游 FFmpeg 预编译包、Boost 1.89 和 Homebrew `miniupnpc` 2.3.3；关闭托盘以避免 Qt 依赖。新应用 `.nxbridge/apps/NXBridge-Sunshine.app` 使用独立标识与临时签名，资源读取本机官方 Sunshine 副本。用户确认后，为新应用启用 macOS 录屏权限。

## 验证证据

- `python3 tests/sunshine_bridge_test.py`：2 项通过，验证证书匹配与不匹配、16 位按键映射、四轴、短按 / 释放顺序，以及断线重连前中和。
- `python3 tests/input_receiver_test.py`：5 项通过，覆盖游戏接收器的认证、拆包、顺序、短按锁存、超时和断开释放。
- 独立应用由 macOS LaunchServices 启动后，H.264 和 HEVC VideoToolbox 编码器初始化成功。直接从终端启动虽有设置中的开关，仍报告无录屏权限；本次使用系统应用启动方式。实验 Pad 通过原版 Moonlight 手柄传输连接，Sunshine 日志确认已匹配指定配对客户端，且其本机套接字与目标游戏建立连接。
- 在无 ADB reverse 的状态下，以显式指定设备的 ADB **模拟触摸事件**进行验证；ADB 用于测试操作，输入数据经 Wi‑Fi 的 Moonlight / Sunshine 原生协议传输。游戏采样确认 +、B、ZL、左右摇杆和同时按 B / 推左摇杆；松手后回零。画面为游戏户外场景。真实人手操作的手感未测试。
- 用户原本的 Sunshine 默认断线超时下，一次按住 B 强制结束客户端的测试约 5.76 秒后归零。本次只对独立实验进程通过启动参数设置 `ping_timeout=2000`，未修改持久 Sunshine 配置；另一次同类测试约 2.10 秒后归零。在该参数下，B 保持 3.5 秒长按后正常释放；恢复串流后没有重放旧 B，新的 B 按下 / 释放正常。连续 10 秒观察未误超时，不能据此推断长期或差网络稳定性。
- 屏幕录制授权后实际串流协商 `hevc_videotoolbox`，系统音频 tap 和 48 kHz 双声道 Opus 编码初始化成功；没有监听平板声音，不能宣称听感通过。端到端输入延迟没有测量。
- `make check` 通过项目文档及元数据检查；它本身不代表功能 / 性能达标。

## 结论与限制

这次的触屏输入已实际通过 Sunshine / Moonlight 原生协议控制单个 BOTW 进程，无需 USB ADB 转发或额外局域网输入服务。两秒超时是实验折中：较长的网络中断可能更快断流，且真实强制断线到中和仍约 2.1 秒。需要继续改善断线保护，并测量真实网络情况下的误断流与用户手感。

视频仍是完整桌面，系统通知和其他窗口可能出现在画面中；窗口级视频、进程级音频、多会话隔离和容量、陀螺仪、震动及端到端延迟尚未验收。证书匹配在单元测试与指定客户端连接中验证；未实测多个同时运行的游戏会话。
