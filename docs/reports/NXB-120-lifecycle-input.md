# NXB-120：暂停时输入中和（验证中）

日期：2026-11-09。任务状态以 `tasks/backlog.json` 为准。

代码检查发现 370 的游戏串流页在 `onStop` 隐藏控件和断开连接，但 `onPause` 本身没有像输入工作台一样立即中和并屏蔽控制器；页面暂停但尚未停止时的行为没有被既有工作台测试覆盖。371 实验补丁在游戏页暂停时先屏蔽并向本会话控制器发送中和，取消旧触点，恢复时等待输入回到中和状态。编辑屏蔽与生命周期屏蔽分别记录，任一仍生效时另一项结束不会解除屏蔽。输入工作台复用同一生命周期屏蔽路径。

## 已验证

- 1372 的 370 离线工作台中通过临时 Android `uinput` 触摸设备按住 ZL，切后台并返回；返回时工作台显示触点与输入中和，旧触点移动不重新触发，释放后新触点可按下并释放。该结果仅验证工作台，不能证明游戏页。
- 371 构建通过，1372 通过受管安装器升级，安装 APK 哈希与构建相同；对 371 重复上述工作台测试，得到相同结果。临时输入设备已退出，未启动游戏或改动存档。原始工作台输出在本机 `.nxbridge/controller-120/370-background-lab-result.json`，该文件随后由 375 测试覆盖；工作台显示的是本地生产输入组件输出，并非网络和游戏采样。
- `adapters/input/moonlight-lifecycle-input-371.patch` 在固定 Moonlight 修订 `b48494cb96bff23d8886c4775cc4f39a1075495d` 的 NXBridge 370 源上独立应用，与构建源一致。

## 合成串流验证与后续修复

1372 使用同一 GameStream 协议的独立合成画面会话测试。用 Android `uinput` 模拟手柄 L 键，并打开 Android 分享选择器，使游戏页处于可见但已暂停状态：371 主机观察到按下 `0x0100` 后中和 `0x0000`，但返回后旧按住的重复事件又产生 `0x0100`。372 仅过滤 Android 的重复计数仍无法阻止该复现，不能把它视为修复。

373 对原始设备 ID 和按键建立保持 / 屏蔽集合，暂停或编辑时记录已有按住，取消事件不冒充物理松开，实际释放后才允许新按下；设备移除时清理相应记录。合成串流上重测，同一模拟手柄序列在主机记录为 `0100 → 0000 → 0100 → 0000`：第二个 `0100` 在旧按住重复被忽略、旧按键释放和全新按下后出现。模拟触屏面键也得到 `1000 → 0000 → 1000 → 0000`，返回后的旧触点移动没有触发；编辑中和暂停后恢复编辑时，模拟手柄没有输出，取消编辑后新按下 / 释放正常。记录分别为本机 `.nxbridge/controller-120/371-game-pause-result.json`（最终为 373）、`373-game-touch-pause-result.json` 和 `373-edit-pause-result.json`。这些是短时模拟输入，未验证真实实体手柄、摇杆或其他设备。

在 373 离线工作台进一步模拟按住后失焦、失焦期间松开：由于松开事件未送达应用，恢复后的第一次新按下被保护机制拦截，松开后第二次才生效。记录为本机 `.nxbridge/controller-120/373-release-away-result.json`。这是实际可复现的易用性缺口，尚未解决，故不将 373 安装到 1402。

373 离线构建、372 / 373 补丁各自独立重放与源文件比对通过，1372 安装 APK 哈希一致；输入接收器 16 项测试及工作台无网络出口检查通过。合成会话已退出、临时服务已结束，原 1372 服务按原启动脚本恢复并处于空闲；没有启动游戏或更改存档。

## 失焦释放提示与诊断

在 1372 Android 13 上使用仅用于采样的 374 诊断构建，记录模拟手柄按键的 Android `KeyEvent`：失焦后仍按住的注入重复事件，在返回后可表现为 `repeatCount=0` 且 `downTime=eventTime` 的普通 DOWN；失焦时松开后的新按下也可表现为同样形式。仅凭这两个字段不能安全地区分这次实验中的两种情况，不能据此推断所有 Android 设备或实体手柄的行为。诊断日志在本机 `.nxbridge/controller-120/374-focus-key-diag.log`；375 构建已移除诊断记录。

375 在被保护的物理按键首次被拦截时显示“请松开手柄按键，再按一次”，提示有 2.5 秒限频，编辑 / 后台抑制期间不弹出。1372 离线工作台验证了提示的实际显示（截图 `.nxbridge/controller-120/375-held-hint.png`）、失焦时松开后首次按下仍被拦截、再次按下恢复；同时复测触屏旧触点不复活。提示没有消除首次按下丢失，也不代替真实实体手柄或游戏页验证。375 离线构建、在 373 文件上独立重放补丁并比对构建源、工作台无网络出口检查通过，安装 APK 哈希一致；本次不启动游戏、不改存档。1402 暂留 370。

后续两台已更新至 377，包含上述保护和提示；新布局验证见 [小手候选布局](NXB-120-compact-preset.md)。首次按下可能被拦截的限制仍未消除。
