# 输入桥接口草案

状态：正式 LAN / 多会话接口草案。已有 [USB 单会话原型](reports/NXB-045.md) 验证游戏输入接入；目标为 Moonlight → NXBridge Rust GameStream 接收端 → 本地会话 IPC → nxnative。Sunshine 输入转发仅属于可选过渡路径。

USB 原型的 ADB 通道、实验令牌和约 1 秒超时不作为正式 LAN 认证 / 延迟承诺。原生协议接入须绑定已配对客户端、控制代次和具体游戏实例，再复用已验证的按键 / 摇杆映射与短按锁存；体感、震动仍独立验收。

可选动作宏的产品范围与验收见 [输入桥迭代需求](input-bridge-requirements.md)。首版为后翻、左右侧跳、招架和滑盾，均由玩家判断触发时机；宏执行器和客户端动作键尚未实现，不是基础串流的前置依赖。

## 接入点

本地 nxnative 副本已有 `dm_pad_set_player`、`dm_pad_players`、`dm_motion_set` 等接口。集成时必须在所选上游修订重新核实 ABI、线程安全和输入合并行为，不能用本地副本的存在证明上游版本已兼容。

每个独立 BOTW 进程接收自己的 player 0 输入。玩家 A / B 是不同进程的会话，不是把单人 BOTW 的 player 0 / player 1 当作两份游戏。

## 本地消息边界

候选为权限受限的 Unix domain socket，显式帧边界和大小限制。实际 JSON / 二进制编码在小规模性能实验后确定；以下为语义契约，不是已经稳定的网络协议。

| 字段 | 语义 |
| --- | --- |
| schema_version | 接口版本，不支持时拒绝 |
| session_id / lease_generation | 固定连接所属会话与当前控制权 |
| sequence | 会话内单调递增，用于丢弃重放 / 过期消息 |
| host_received_ns | 同一 Mac 单调时钟上的入口时间 |
| buttons | 映射后的 Npad 按键位图 |
| lx / ly / rx / ry | 有范围校验的归一化摇杆值；转换到运行时范围 |
| motion | 可选加速度 / 角速度及坐标系、单位、采样时间 |

- Host 创建会话时绑定 socket；不接受客户端指定任意本机路径或 PID。
- 每会话独立序列和输入状态；只对当前代次的数据生效。
- 轴值用最新状态；短按的按下 / 松开必须保序或锁存至游戏采样，不能因“只保留最后一帧”丢掉点击。
- 动作宏额外要求按键与方向作为一致快照发布，保留同键多次按下之间的释放采样，并区分人工 / 宏输入归属。现有单次短按锁存不等于已具备宏的步骤时序和采样确认；详细规则以迭代需求为准。
- 关闭、断线、超时或代次变更时，强制发送全释放并清空体感源。超时目标初设 250 ms，需故障测试验证。
- 同机排队时间与游戏实际采样时间分开记录。接收到了消息不代表游戏已经读到输入。
- 不经过全局键鼠事件，不依赖前台窗口。运行时本地物理手柄路径要有选择器，避免同一手柄同时驱动三个进程。
- 顺序、非法范围、重复连接、短按、长按、焦点切换、断线、旧代次输入均有行为测试。

## 时钟与反馈

客户端时间只用于本端间隔测量，未经校时不得与主机时间直接相减。输入到画面的最终延迟用外部测量交叉验证。

体感先明确 Apple / Switch 坐标系和单位；先验证按钮和双摇杆，再做 BOTW 体感瞄准 / 谜题。震动回传属于另一方向的消息，独立验收。任何一端缺少能力都显示实际支持状态。

上游 `DM_CTL` 文件轮询约 100 ms，是调试入口；不得直接用它宣称低延迟输入桥已经实现。
